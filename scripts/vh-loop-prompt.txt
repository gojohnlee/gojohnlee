토큰 아끼기(사용자 10-27 — 모든 턴이 지금까지의 대화 전체를 다시 읽는다. 턴 수와 읽는 양이 곧 비용):
- 명령은 묶어서 한 번에(예: 빌드·테스트·커밋을 한 명령으로). 같은 파일을 다시 읽지 않는다. Read는 offset/limit, 나머지는 grep.
- 명령 출력은 짧게(| tail -20, grep). 빌드·테스트·게임 시험 출력 전체, diag 전체, 로그 전체, history.md·codemap·decisions 통째로 읽기 금지. 전체 회귀는 run.ps1 요약 줄만.
- 회차 상한(사용자 11-11): 60턴·대화 10만 토큰을 넘으면 루프가 끊는다. 45턴쯤 넘으면 새 조각을 시작하지 말고, 끝난 데까지 커밋·progress에 남은 것을 적고
  "LOOP: 이어 함 <남은 것>"으로 끝낸다(진척 없음으로 안 셈, 3번 연속까지). 다음 회차는 git status·progress로 이어 간다.
- 일찍 손 놓지 않기(사용자 11-13 — 회차 494~504가 30초·10턴 안에 "크다·설계부터·다음 회차에"로 끝나 11번 내리 아무것도 안 하고 루프가 멈춰 PC가 꺼짐):
  "이어 함"은 위 상한(45턴쯤) 때만. 40턴 안에 "이어 함"으로 끝내면 루프가 진척 없음으로 센다.
  "일이 크다·한 회차에 못 끝낸다·설계가 먼저다·자리를 더 봐야 한다"는 끝낼 까닭이 아니다. 이번 회차에 빌드·Core 테스트가 통과하는
  가장 작은 조각(예: 한 자리만 연결 + Core 테스트, 새 vh_ 시험 뼈대)을 직접 만들고 시험·커밋한다. 조사만 하고 끝내지 않는다.
  설계는 progress·decisions에 이미 적힌 사용자 규칙을 그대로 따른다(다시 정할 것이 아니다). 정말 없을 때만 5번 기본안.
- 출력에 사용자에게 묻는 말을 쓰지 않는다(아무도 안 읽는다). 멈추고 물을 것은 LOOP: NEED_USER 버그 위험만(5번 조건 — 버그 위험이 아니면 질문은 history에 남기고 그 일만 보류, 다른 일을 함).
- 게임 시험은 묻지 않고 돌린다. pc-howto의 "게임이 켜져 있으면 묻는다"는 사용자가 앞에 있는 대화 세션용이다(직접 플레이 중이면 시험 스크립트가 알아서 미룸).
- 서브에이전트(사용자 11-11, decisions 2절): 도우미는 노력을 바꿀 때만 쓴다. 집 걸음 일(걸음 기록 수치 고치기)은 메인이 직접(기준은 decisions "집 걸음 기준" grep). 원인 찾기 버그(시험 FAIL·로그 예외·이상 동작)만 메인이 한 번 보고 바로 안 보이면 vh-debug(Opus·엑스트라 하이)에 증상·시험 이름·diag·로그 발췌를 붙여 넘기고 결과를 받아 diff 검토·빌드·시험·커밋. 그 밖(단순 오타·빌드 경고·문서)은 쓰지 않는다. -std·Fable은 쓰지 않는다.

3. 게임 시험(묻지 않고 돌림, docs/valheim/pc-howto.txt 5번 방법, 바꾼 코드와 닿는 시험만 — codemap "시험 고르기"). 시험 시점·환경은 decisions.txt 3절.
   긴 시험(사용자 11-13, 최종 실전 시험처럼 30분 넘는 것): $env:VH_MAXMIN="<예상 분의 1.5배>"(기본 30분이면 강제 종료)를 같이 주고, 명령은 run_in_background로 돌려 끝 알림을 기다린다
   (도구 한 번은 10분까지). 기다리는 동안 다른 명령을 자주 부르지 않는다(턴·토큰). 시험 게임이 도는 동안 루프는 회차를 240분에 안 끊고 720분까지 기다린다.
   FAIL이면 그 시험의 diag '=== 이름' 부분과 로그 오류 줄만(bash scripts/vh-log.sh) 보고 원인을 찾아 고친 뒤 한 번 더 돌린다. 재실행 PASS로 끝내지 않는다:
   연속 FAIL·단독 PASS면 시작·FAIL 순간·끝 상태를 비교해 시험이 남긴 것이면 TestKit, 일꾼 상태면 본체를 고친다.
   복제·소실·저장 손상·복원 실패는 막는 문제: 원인을 못 찾아도 넘어가지 않고 그것부터. 그 밖은 한 회차 안에 못 풀면 Errors.txt에 적고(규칙은 그 파일 머리) 다음 일로, PASS로 치지 않는다.
   새 FAIL·예외는 먼저 Errors.txt·Errors-resolved.txt를 시험 이름으로 grep — 발생 순서·시작 상태까지 같을 때만 같은 ID.
4. 빌드·Core 통과분만 valheim에 커밋·푸시(dist DLL 포함). progress "지금"·"다음"을 고친다.
   history.md 맨 위에 bash scripts/vh-history-add.sh로 회차 기록(꼴은 그 스크립트 머리 주석, 쉬운 말, history.md는 열지 않음). "지금" 맨 위에 같은 요약 한 줄, 3개 넘으면 맨 아래 것을 지움.
   새 파일·이동은 codemap, 단계가 끝나면 "구현 단계" 표, 기본안은 decisions.txt 맞는 절(어긋나는 옛 줄은 지움)도 같은 커밋에. status.txt·loop-stop.txt·loop-pause.txt는 건드리지 않는다.
   완료 기록(실제 파일을 바꾼 커밋 또는 이 근거가 붙은 것을 루프가 진척으로 센다, 3회차 연속 없으면 루프가 지금 일을 넘기라는 메모를 줌 — 안 멈춤):
   - 코드: "[끝, 회차 N — 커밋 <해시7> · 시험 <이름> PASS <n/n>, …]"(N = status.txt "회차:"). 코드 커밋을 먼저 푸시하고 git log로 해시를 다시 확인한 뒤 기록 커밋.
   - 시험 못 함: "[구현 완료·검증 대기, 회차 N — 커밋 <해시> · 시험 못 함: <이유>]"(끝 아님 — 다음 회차가 먼저 시험).
   - 문서만: "[끝, 회차 N — 문서만: <파일·무엇>]". 문제를 닫을 때 Errors-resolved 줄 "수정(회차·커밋)"에 해시.
5. 새 게임플레이 결정이 꼭 필요하면 기본안으로 하고 decisions.txt에 [기본안·확인 필요].
   사용자 답이 있어야 하는 일(기본안도 못 정함)인데 버그 위험이 아니면(사용자 11-13): 멈추지도 묻고 기다리지도 않는다. history에 "### 질문"으로 남기고
   그 일만 progress에 "[보류: 사용자 답 기다림 — 질문 MM-dd]"로 둔 뒤, 답과 상관없는 다른 일("다음"의 다음 항목·Errors.txt)을 이 회차에 한다. 답이 오면(UserRequest) 그 일을 다시 연다.
   멈추는 NEED_USER는 사용자 답 없이 가면 게임에 버그가 날 수 있을 때만(물건 복제·소실, 저장 손상, 작업 복원 실패, 사용자가 정한 것과 부딪혀 고치면 다른 게 깨짐).
   그때 마지막 줄은 "LOOP: NEED_USER 버그 위험: <무슨 버그가 날 수 있나> — <물을 것>". "버그 위험:"이 없으면 루프는 안 멈추고 다음 회차에 그 일을 보류하고 다른 일을 하라고 한다.
   status.txt에 "루프 메모:" 줄이 있으면 지난 회차에 대한 루프의 지시다 — 그것부터 따른다(멈추지 않고 넘긴 까닭).

마지막 줄은 반드시 하나(한국어 한 줄, 120자 이내):
LOOP: DONE <한 일> | LOOP: 이어 함 <남은 것> | LOOP: FAIL <시험 이름> <못 고친 이유> | LOOP: NEED_USER 버그 위험: <버그> — <물을 것>
LOOP: ALLDONE <요청·"다음"·구현 단계 ⑮까지 전부 끝·보류이고 Errors.txt에 관찰 중·조사 중이 없을 때만>
  ALLDONE 직전: 전체 회귀(codemap "시험 고르기" B1~B12 + 실제 재시작)가 전부 PASS면 태그 valheim-stable을 그 커밋으로 옮기고 status.txt "플레이용 빌드:" 줄(loop-plan.txt). FAIL이면 안 옮김.
