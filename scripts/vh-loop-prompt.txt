발헤임 무인 루프(scripts/vh-loop.ps1)의 한 회차다. 사용자는 자리에 없다. 묻지 말고 스스로 진행한다.

토큰 아끼기(사용자 10-27 — 모든 턴이 지금까지의 대화 전체를 다시 읽는다. 턴 수와 읽는 양이 곧 비용):
- 명령은 묶어서 한 번에(예: 빌드·테스트·커밋을 한 명령으로). 같은 파일을 다시 읽지 않는다. Read는 offset/limit, 나머지는 grep.
- 명령 출력은 짧게(| tail -20, grep). 빌드·테스트·게임 시험 출력 전체, diag 전체, 로그 전체, history.md·codemap·decisions 통째로 읽기 금지.
- 서브에이전트는 쓰지 않는다. 예외: 막는 문제(복제·소실·저장 손상·복원 실패)를 직접 한 번 찾아도 원인을 모를 때만 vh-debug 하나, 결과를 기다려 받는다.

맨 먼저 한 명령으로: powershell -NoProfile -ExecutionPolicy Bypass -File scripts/vh-loop-restart.ps1; echo "G=$env:VH_GAME_UPDATE"; git status --short | head
 (restart 결과가 오류면 이번 회차 history "자세히"에 그 줄.)
0. docs/valheim/UserRequest.txt 구분선 아래에 덩어리가 남아 있으면 scripts/vh-loop-request.txt를 읽고 그것부터(이번 회차는 요청이 "다음"보다 우선).
1. docs/valheim/progress.txt "지금"·"다음"을 읽는다. Errors.txt는 제목 줄만(grep -n '^E[0-9]' docs/valheim/Errors.txt), 이번 일과 닿는 항목만 그 부분.
   지난 회차가 남긴 변경이 있으면(git status) 이어 간다.
1-0. G(VH_GAME_UPDATE)가 있으면 "다음" 맨 앞에 "★ 게임 업데이트 <값>: 전체 회귀"(codemap "시험 고르기" 바이옴 완료 꼴 B1~B7 + 실제 재시작)를 넣고 첫 묶음부터.
   FAIL이면 바뀐 게임 코드를 디컴파일해 확인하고 codemap "확인된 게임 사실"을 고친다. G가 없어도 그 덩어리가 남았으면 이어 간다.
1-1. 순서(decisions.txt 2절): 나중에 고치면 비싼 바탕부터. 남은 순서: ⑫ 평원 → 전투 보강 → ⑬ 안개땅 → ⑭ 애쉬랜드 → ⑮ 딥노스. 하지 않는 것은 decisions.txt 16절.
2. "다음"의 안 끝난 첫 항목 하나만. 크면 빌드·테스트가 통과하는 한 조각만(남은 것은 progress에). 조각이 전부 [끝]인 ★ 덩어리는 먼저 지운다.
   이득이 작거나 위험 대비 작은 항목은 "[보류: 이유]"로 두고 다음 항목으로(보류만 하고 끝내지 않음).
   "다음"이 비면 progress "구현 단계"의 첫 [ ]·[~] 단계를 concept-v1.txt 그 장(grep)으로 조각 몇 개로 나눠 "다음"에 적고 첫 조각을 한다(⑭·⑮는 ⑬까지 [x]·보류 뒤).
2-1. 꺼 둔 도구(웹 검색·스킬·MCP)가 꼭 필요해 막히면 progress "다음"에 "도구 필요: 무엇·왜"를 남기고 그 조각은 건너뛴다(보류처럼, 다음 항목으로).
3. 게임 시험(묻지 않고 돌림, docs/valheim/pc-howto.txt 5번 방법, 바꾼 코드와 닿는 시험만 — codemap "시험 고르기"). 시험 시점·환경은 decisions.txt 3절.
   FAIL이면 그 시험의 diag '=== 이름' 부분과 로그 오류 줄만 보고 원인을 찾아 고친 뒤 한 번 더 돌린다. 재실행 PASS로 끝내지 않는다:
   연속 FAIL·단독 PASS면 시작·FAIL 순간·끝 상태를 비교해 시험이 남긴 것이면 TestKit, 일꾼 상태면 본체를 고친다.
   복제·소실·저장 손상·복원 실패는 막는 문제: 원인을 못 찾아도 넘어가지 않고 그것부터. 그 밖은 한 회차 안에 못 풀면 Errors.txt에 적고(규칙은 그 파일 머리) 다음 일로, PASS로 치지 않는다.
   새 FAIL·예외는 먼저 Errors.txt·Errors-resolved.txt를 시험 이름으로 grep — 발생 순서·시작 상태까지 같을 때만 같은 ID.
4. 빌드·Core 통과분만 valheim에 커밋·푸시(dist DLL 포함). progress "지금"·"다음"을 고친다.
   history.md 맨 위에 bash scripts/vh-history-add.sh로 회차 기록(꼴은 그 스크립트 머리 주석, 쉬운 말, history.md는 열지 않음). "지금" 맨 위에 같은 요약 한 줄, 3개 넘으면 맨 아래 것을 지움.
   새 파일·이동은 codemap, 단계가 끝나면 "구현 단계" 표, 기본안은 decisions.txt 맞는 절(어긋나는 옛 줄은 지움)도 같은 커밋에. status.txt·loop-stop.txt·loop-pause.txt는 건드리지 않는다.
   완료 기록(이 근거가 붙은 것만 루프가 진척으로 센다, 3회차 연속 없으면 멈춤):
   - 코드: "[끝, 회차 N — 커밋 <해시7> · 시험 <이름> PASS <n/n>, …]"(N = status.txt "회차:"). 코드 커밋을 먼저 푸시하고 git log로 해시를 다시 확인한 뒤 기록 커밋.
   - 시험 못 함: "[구현 완료·검증 대기, 회차 N — 커밋 <해시> · 시험 못 함: <이유>]"(끝 아님 — 다음 회차가 먼저 시험).
   - 문서만: "[끝, 회차 N — 문서만: <파일·무엇>]". 문제를 닫을 때 Errors-resolved 줄 "수정(회차·커밋)"에 해시.
5. 새 게임플레이 결정이 꼭 필요하면 기본안으로 하고 decisions.txt에 [기본안·확인 필요]. 기본안도 없어 더 못 갈 때만 NEED_USER(질문 꼴은 vh-loop-request.txt).

마지막 줄은 반드시 하나(한국어 한 줄, 120자 이내):
LOOP: DONE <한 일> | LOOP: FAIL <시험 이름> <못 고친 이유> | LOOP: NEED_USER <물을 것>
LOOP: ALLDONE <요청·"다음"·구현 단계 ⑮까지 전부 끝·보류일 때만>
