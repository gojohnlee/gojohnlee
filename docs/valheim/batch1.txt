2. 작업 (이 순서대로)
======================================================================
작업 1. !상자 지정을 ZDO 기준으로 (멀티: 호스트에 상자 인스턴스가 없어도 되게)
- Commands.SetChest(231행 근처): Chests.FromId(who.Hover)가 FindInstance라, 호스트가 멀고 NPC도 나가 있어 거점 구역이 안 불러와져 있으면
  친구가 상자 앞에서 해도 chestNone. → ZDOMan.instance.GetZDO(who.Hover)로 위치(InRange)·상자인지(프리팹에 Container,
  수레·배 제외는 Chests.NearBase와 같은 기준)를 판정하고 그 ZDOID로 Assign. FromId 자체는 그대로(DeathTest·GraveJob이 씀).
- 완료: 빌드. 게임 확인은 작업 4의 vh_peertest.

작업 2. 작업 상태 저장 (대기열·질문 대기·하던 일) — 설계 risks.txt "작업 상태 저장 설계"
- 지금: WorkerAI.QueuedWork = {Label, Resume(IWorkerJob), Start(람다), Ready(람다)}, Departures.s_pending = 정적 Dictionary<WorkerNpc, Pending{Result, Cmd, Who, AskedAt}>.
  큐에 넣는 곳: Departures.cs 64행·341행(채집, 341은 Ready=아침), Commands.cs 181행(탐험), WorkerAI.Interrupt(하던 일 맨 앞).
- Core에 데이터 모양: WorkItem{종류(채집/탐험/…), 물건, 수량, 말한 사람 이름, 급함, 고른 장소 구역, 기다릴 조건(없음/아침)},
  PendingData{질문 종류, 대안 구역, 조건 물건, 물은 시각, 명령}. 텍스트 저장·불러오기(다른 Book들처럼 ; , = 구분) + 테스트.
- Plugin: QueuedWork가 WorkItem을 들고, Start/Ready는 WorkItem에서 만든다. 하던 일(Resume)은 큰 단계만 WorkItem으로
  (채집이면 물건·남은 수량·목표 구역; 세부 단계는 처음부터 다시). NPC ZDO "vh_queue"·"vh_pending"(NPC마다)에 저장,
  NPC가 생길 때 불러옴. 불러왔을 때 질문이 3분 넘었으면 보류 처리(answer.timeout과 같게).
- Speaker는 이름만 저장(캐릭터 ZDOID는 다시 접속하면 바뀜). 대답 받을 사람 판단이 이름으로 되는지 확인.
- codemap.txt ZDO 저장 키 줄에 vh_queue vh_pending 추가.

작업 3. 밝혀진 곳은 안다 (사용자 결정 2026-10-21, progress "다음 4-1")
- 지도에 밝혀진 구역(Scout.Explored — 지도 공유로 남이 밝힌 곳 포함)의 자원은 가 보지 않아도 지식에 넣는다. 안 밝혀진 곳은 지금처럼 탐험.
  적·도구 배우기는 그대로.
- 방법: Senses.Look과 같은 셈을 구역 단위로: 구역 ZDO(ZDOMan.FindSectorObjects(zone, new SimulationDistance(0,0)))
  → ResourceCatalog.Get(prefab) → Brain.Get().Saw(seen, full=[그 구역], now), MarkLooked, SetBiome(Scout.BiomeAt(구역 중심)).
  월드 불러올 때 한 번 + 몇 초마다 조금씩(한 번에 구역 N개, 프레임 끊김 방지) 새로 밝혀진 구역만.
- 주의: Scout.Explored는 구역 중심 한 점만 본다 → 구역 안 몇 점(중심+네 모서리 안쪽) 중 하나라도 밝혀졌으면 밝혀진 것으로.
  생성 안 된 구역(밝혀졌지만 ZDO 없음)은 건드리지 않음(모름 그대로 → 탐험).
- 반응: "구리요? 처음이라 좀 걸려요"·밝혀진 곳 찾기 15분은 안 밝혀진 곳에만 남는다. Departure 입력이 바뀌면 Core 테스트도.
- ExploreTest는 시험 동안 이 스위치를 끈다(기존 시험 그대로 통과해야 회귀가 깨끗함). 이 기능 시험은 작업 4의 vh_departtest 안에.

작업 4. 새 시험 (지금 시험 틀 그대로, 기존 시험 파일은 안 고침, TestRunner에 등록만)
- vh_departtest (Departures.TestAutoGo=false): 재고 충분 질문 → "응" 대답, 곧 밤 질문 → 대기열(아침 조건), 죽은 곳 질문,
  위험 조건(미드) → 상자에 넣으면 자동 출발, 3분 무응답 보류(시간은 시험용으로 줄여도 됨), 하던 일 중 새 명령(급함/아님),
  저장 왕복(대기열·질문 있는 채로 NPC를 지우고 다시 불러서 그대로인지), 밝혀진 곳 아는지(작업 3, 스위치 켬/끔 비교).
- vh_peertest (risks.txt "혼자 하는 멀티 시험" A):
  1) 일하는 중·상자 쓰는 중·싸우는 중·질문 대기 중마다 NPC ZDO를 없는 uid로 SetOwner → 그동안 ZDO·상자·인벤토리 안 씀,
     예외 0, 상자 잠금 풀림, 2초 안에 호스트가 되찾고(바닐라 ReleaseNearbyZDOS) 하던 일 이어감, 물건 총량 같음.
  2) 가짜 Speaker(이름, 호스트에서 먼 캐릭터 ZDOID)로 Commands.Handle: 대답 받는 쪽·대기열·!같이 가자·!상자(작업 1) 예외 없음.
  3) 손님 흉내(IsServer false처럼 도는 플래그)로 모드 Update 경로가 아무것도 안 쓰는지.
- 각 시험은 판정마다 diag에 한 줄(기존 시험과 같은 Check 방식). 시험 코드 예외는 바로 FAIL(TestRunner.Safe 그대로).
- valheim-test.ps1의 시험 목록 설명(progress.txt PC 세션 시작 순서 5)에 두 시험 이름 추가.
