사용자 → 무인 루프 요청 (밖에서 GitHub 앱·웹으로 이 파일을 고쳐 커밋한다)
- 요청 하나 = 한 덩어리. 첫 줄이 요청의 이름 역할을 한다. 덩어리 사이는 빈 줄.
- 요청 사이에는 빈 줄을 꼭 넣는다(붙여 써도 따로 보려고 하지만 빈 줄이 확실하다).
- 답은 UserReply.txt에 먼저 온다: 회차는 시작하자마자 답부터 쓰고, 돌고 있는 회차가 있으면 15분 백업 때 확인해
  답 전용 세션이 15~30분 안에 답한다(질문은 바로 답, 일은 "받음:"으로 받고 다음 회차가 맨 먼저 함). 이 파일은 루프가 고치지 않는다(끝난 요청 정리만).
- 루프가 멈춰 있으면(사용자 확인 필요·할 일 없음·진척 없음 등) 이 파일이 바뀌면 5분 안에 다시 돈다. 아주 멈추려면 loop-stop.txt를 만든다.
- 끝난 요청(UserReply에 "요청:" 답)은 답이 쓰인 지 24시간 뒤 루프가 답과 함께 history.md "끝난 요청과 답"으로 옮기고 지운다. 같은 걸 다시 시키려면 새로 쓴다.

- docs/valheim/Errors.txt = 미해결 문제만(간헐 FAIL·로그 예외·이상 동작). 매 회차 progress "지금·다음"과 함께 이 파일만 읽는다. 항목 칸은 이것만:
  ID/상태(E001~, 조사 중·관찰 중; 막는 문제면 "막음: <멈추는 기능 확장 범위>"), 증상·발생 조건(시험 이름·FAIL 문구·단독/연속 순서),
  근거(발생 커밋·시험명·로그 위치, 발생 N회·마지막 근거만), 확인된 사실(모르는 건 "미확인"), 다음 확인.
- docs/valheim/Errors-resolved.txt = 해결된 것 한 줄씩(ID·시험명·FAIL 문구·원인·수정 커밋·검증 결과). 평소에 안 읽고 새 FAIL 때만 grep.
- 해결로 닫는 조건: 원인 확인 + 수정 + 원래 실패 조건(같은 순서·시작 상태)에서 검증. 되도록 원인을 일부러 만들어 고치기 전 FAIL·고친 뒤 PASS.
  재실행 PASS나 연속 PASS 횟수만으로는 닫지 않고 "관찰 중"(40% 실패면 아무것도 안 고쳐도 5번 연속 통과가 7.8%). 막음 항목은 관찰 중으로도 풀지 않는다.
- 같은 문제인지: 시험 이름+FAIL 문구는 찾는 용도만. 발생 순서·시작 상태(TestKit 시작·FAIL 순간 기록)까지 대조해 같을 때만 같은 ID로 묶고 발생 횟수·마지막 근거만 고친다.
  다르거나 대조할 기록이 없으면 새 ID에 "비슷: E00x". Errors-resolved.txt에서 찾아도 이 대조를 거친 뒤에만 다시 연다(재발 횟수 표시).
- 순서: 막음 > 조사 중 > 관찰 중(관찰 중은 따로 시간 안 쓰고 그 시험을 돌릴 때만 본다).
- 회차 기록(progress "지금"·history)에는 ID와 그 회차에 새로 확인한 사실 한 줄을 남긴다(ID만 쓰지 않음).
