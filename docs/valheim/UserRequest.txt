사용자 → 무인 루프 요청 (밖에서 GitHub 앱·웹으로 이 파일을 고쳐 커밋한다)
- 요청 하나 = 한 덩어리. 첫 줄이 요청의 이름 역할을 한다. 덩어리 사이는 빈 줄.
- 요청 사이에는 빈 줄을 꼭 넣는다(붙여 써도 따로 보려고 하지만 빈 줄이 확실하다).
- 답은 history.md 맨 위에 "### 요청 · 날짜 · 이름"으로 온다: 회차는 시작하자마자 답부터 쓰고, 돌고 있는 회차가 있으면 15분 백업 때 확인해
  답 전용 세션이 15~30분 안에 답한다(질문은 바로 답, 일은 "[받음 시각]"을 앞에 붙여 두고 다음 회차가 맨 먼저 함). 가져간 요청은 루프가 이 파일에서 지운다.
- 루프가 멈춰 있으면(사용자 확인 필요·할 일 없음·진척 없음 등) 이 파일이 바뀌면 5분 안에 다시 돈다. 아주 멈추려면 loop-stop.txt를 만든다.
- 같은 걸 다시 시키려면 새로 쓴다(지워진 요청은 history.md에 남아 있다).
- 구분선 아래만 요청으로 읽는다.

일꾼 대사 번역투 고치기(사용자 11-12, 실플레이에서 봄)
"불씨를 죽이지 마. 어둠도 길을 찾으니까."(Speech.cs bt.solo.night), "밤의 숲에선 길이 두 배로 갈라져 보여."(nightNoExplore) — 한국어답지 않고 영어를 옮긴 말 같다.
1. 이 두 줄부터 사람이 실제로 할 법한 말로: 예) "불 꺼뜨리지 마. 꺼지면 밤것들이 몰려와." / "밤 숲은 길이 다 비슷해 보여서 헷갈려." (그대로 안 써도 됨, 뜻·말투만 맞게)
2. Speech.cs 한국어 대사 전부 훑어서 같은 꼴 고치기: 영어 직역 표현(~를 죽이다·~가 길을 찾다·두 배로·~의 것이다 등), 뜻이 바로 안 들어오는 비유, 일꾼마다 정한 말투(반말·짧음)와 안 맞는 문어체. 게임 안에서 한 번 듣고 알아들을 수 있어야 함.
3. 고친 줄은 전/후를 history에 표로(많으면 묶음별 개수+대표 몇 줄). 자리표시자({partner|은} 등)·키 이름·대사 개수는 그대로. 단순 문구라 vh-standard 같은 싼 에이전트에 맡겨도 되고, 메인은 검토만.
