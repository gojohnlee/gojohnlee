사용자 → 무인 루프 요청 (밖에서 GitHub 앱·웹으로 이 파일을 고쳐 커밋한다)
- 요청 하나 = 한 덩어리. 첫 줄이 요청의 이름 역할을 한다. 덩어리 사이는 빈 줄.
- 요청 사이에는 빈 줄을 꼭 넣는다(붙여 써도 따로 보려고 하지만 빈 줄이 확실하다).
- 답은 history.md 맨 위에 "### 요청 · 날짜 · 이름"으로 온다: 회차는 시작하자마자 답부터 쓰고, 돌고 있는 회차가 있으면 15분 백업 때 확인해
  답 전용 세션이 15~30분 안에 답한다(질문은 바로 답, 일은 "[받음 시각]"을 앞에 붙여 두고 다음 회차가 맨 먼저 함). 가져간 요청은 루프가 이 파일에서 지운다.
- 루프가 멈춰 있으면(사용자 확인 필요·할 일 없음·진척 없음 등) 이 파일이 바뀌면 5분 안에 다시 돈다. 아주 멈추려면 loop-stop.txt를 만든다.
- 같은 걸 다시 시키려면 새로 쓴다(지워진 요청은 history.md에 남아 있다).
- 구분선 아래만 요청으로 읽는다.

루프 멈춤 오판·할 일 표시(클라우드 리뷰 11-11, 사용자 승인) — 맨 먼저
1. vh-loop.ps1 Test-RoundResult: 회차 385·386·387이 커밋+시험 전부 통과인데 [끝] 줄에 "PASS" 낱말이 없어 "끝낸 것 없음" 3번 → 멈춤·PC 꺼짐. PASS가 없어도 n/n(앞뒤 같은 수)이면 통과로 센다. 기록 꼴(vh-loop-prompt.txt 31줄 "시험 <이름> PASS <n/n>")도 지킨다.
2. vh-loop.ps1 Get-Todo: progress "다음"이 ★ 없이 "요청 …" 줄이라 status.txt "할 일"이 늘 (없음). "요청 "으로 시작하는 줄 중 안 끝난 첫 줄(120자)을 읽게.

게임은 항상 최신 버전으로(사용자 11-11 — 업데이트가 계속 나옴)
1. 게임 업데이트를 감지하면(이미 있는 VH_GAME_UPDATE) 전체 회귀에 더해: 비공개 gojohnlee/valheim-refs main의 DLL 3개·README를 새 버전으로 올리고(PC에서 못 올리면 이유를 history에), codemap "확인된 게임 사실" 머리·decisions·vh-loop.ps1 GameNote의 "1.0.20 기준" 글자를 지금 버전으로. 옛 버전에서 확인한 사실은 그 줄에 버전을 남긴다.
2. 지금 1.0.21로 위 1을 한 번 한다(전체 회귀는 valheim-stable 요청의 남은 묶음이 겸함).
3. 게임 코드를 베낀 곳(FarZones의 게임 함수 복사본 등)은 업데이트 회차에 새 디컴파일과 비교해 다르면 맞춘다. 이름 글자로 건 패치·내부 필드 읽기가 새 버전에서 못 찾으면 그 기능만 끄고 로그·채팅에 한 줄.

일꾼 기억을 월드별 파일로(사용자 11-11) — 길 기억(집 안 걷기 ②)과 같이

2. 옛 저장 읽기: 파일이 없고 ZDO에 있으면 한 번 옮기고 ZDO에서 뺀다.
3. Senses.SaveMemory의 PrepareSave 넣었다 빼기(ZDOExtraData.s_saveStrings 복사)는 지운다. E072 고침(저장 전 합치기)은 E072가 닫힐 때까지 남기고, 기억과 무관하게 필요한지 history에 한 줄.

   vh_sets·vh_refill·vh_farms·vh_personal·vh_debt는 작으니 그대로 ZDO.

리팩터링 허용(사용자 11-11 "굳이 안 할 이유는 없지") — 11-11 순서의 맨 뒤, 덩어리마다 한 회차
0. decisions 2절의 "중복 정리만 하는 리팩터링은 안 한다"·"큰 파일은 고칠 일이 생길 때 같이 쪼갠다" 줄을 지우고 새 규칙으로: 리팩터링 허용 — 동작은 안 바꿈, 한 번에 한 덩어리, 전후로 관련 시험, 새 FAIL이면 되돌리고 history에 이유, 사용자 기능 요청·막는 문제보다 뒤. progress 결정 모음의 같은 줄도 맞춘다.

넓게 본 리뷰 5개(클라우드 리뷰 11-11 둘째, 게임플레이 안 바뀜)
1. 회차 길이 상한: token-report 기준 회차 380 한 번(294턴, 마지막 대화 33.7만)이 388만으로 회차 361~379 스무 회차 합(464만)에 가깝다 — 턴이 길수록 다시 읽는 양이 제곱으로 는다. vh-loop-prompt에 "60턴쯤(또는 대화가 10만을 넘으면) progress에 이어 할 곳을 적고 회차를 끝낸다(LOOP: 이어 함)"를 넣고, 루프는 그 끝을 진척 없음으로 세지 않는다. 전체 회귀는 묶음 실행기(run.ps1)를 스크립트가 돌리고 회차는 요약만 읽게. 전후 수치를 token-report에.
2. 플레이용 빌드(valheim-stable) 회귀에 멀티 묶음 추가: 지금 B1~B11은 guest*·join을 "멀티 시험이라 뺌" → 친구와 같이 하는 게 목표인데 태그가 멀티를 안 본다(vh_guestchesttest 마지막 기록 10-31). 묶음 B12 = vh-server.ps1 서버 + 손님으로 vh_jointest;vh_guestcmdtest;vh_guestchesttest;vh_guestrestart. PASS해야 태그.
3. 빌드 표시: Plugin.Version이 10-21부터 "0.3.8" 그대로라 로그로 어느 빌드인지 모른다. 빌드 때 커밋 해시7·빌드 시각을 DLL에 넣어 시작 로그·"!상태"·diag 머리에 "0.3.8+<해시>"로. (1.0 번호는 사용자가 배포할 때.)
4. 거점 상자 찾기 캐시: Chests.Candidates·BaseStock·Tidy·Pens·PersonalChests(×3)가 부를 때마다 Senses.Nearby(거점 125m = 5×5구역 ZDO 전부 훑기, 캐시 없음 — BaseStock.Count만 0.5초 캐시), Chests.NearBase 호출 자리 약 40곳. 요청 "큰 집 성능 ③" 측정 때 이 훑기 횟수·시간을 먼저 재고, 크면 거점별 상자 목록 하나(1~2초 갱신 또는 상자 ZDO 생김·사라짐 때)로 모은다. 같은 훑기 줄 6곳도 Chests 하나로.
5. 기능 끄기 스위치: 지금 BepInEx 설정은 4개(SaveWork·KnowExplored·ClaudeChat·RunPlans)뿐. 친구와 하다 문제가 나면 모드를 통째로 빼야 한다. 기본 켬으로 스위치 추가 — 사람끼리 상자 동시 열기(SharedChests·SharedGuest·SharedCraft), 먼 구역 유지(FarZones), 쉴 때 하는 일, 상자 정리·밤사이 정산. 끄면 그 기능의 패치·틱만 쉰다. pc-howto에 끄는 법 두 줄.
