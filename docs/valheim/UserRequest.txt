사용자 → 무인 루프 요청 (밖에서 GitHub 앱·웹으로 이 파일을 고쳐 커밋한다)
- 요청 하나 = 한 덩어리. 첫 줄이 요청의 이름 역할을 한다. 덩어리 사이는 빈 줄.
- 요청 사이에는 빈 줄을 꼭 넣는다(붙여 써도 따로 보려고 하지만 빈 줄이 확실하다).
- 답은 history.md 맨 위에 "### 요청 · 날짜 · 이름"으로 온다: 회차는 시작하자마자 답부터 쓰고, 돌고 있는 회차가 있으면 15분 백업 때 확인해
  답 전용 세션이 15~30분 안에 답한다(질문은 바로 답, 일은 "[받음 시각]"을 앞에 붙여 두고 다음 회차가 맨 먼저 함). 가져간 요청은 루프가 이 파일에서 지운다.
- 루프가 멈춰 있으면(사용자 확인 필요·할 일 없음·진척 없음 등) 이 파일이 바뀌면 5분 안에 다시 돈다. 아주 멈추려면 loop-stop.txt를 만든다.
- 같은 걸 다시 시키려면 새로 쓴다(지워진 요청은 history.md에 남아 있다).
- 구분선 아래만 요청으로 읽는다.

[받음 11-11 00:23] 사냥·솎기 떨굼 기다림 줄이기 (15초·60초는 너무 김, 재서 맞추기)
- 지금 GatherJob 사냥은 떨굼이 없으면 LootWait 15초, 쓰러진 몸이 있으면 LootWaitBody 60초까지 기다린다(회차 380). 너무 길다.
- 게임 코드(1.0.21 Ragdoll): 죽은 뒤 m_ttl초가 지나면 InvokeRepeating(DestroyNow, m_ttl, 1초) → 몸 주인이면 SpawnLoot 하고 같은 호출에서 몸을 지운다. 즉 몸이 사라지는 순간 떨굼이 같이 생긴다.
- 먼저 잴 것(로그로 찍어 history.md에 숫자 적기): 사냥감별(멧돼지·사슴·목 등, 솎기 대상도) Ragdoll 프리팹 m_ttl 값, hunttest에서 죽은 순간 → 몸 사라짐 → 일꾼 눈에 떨굼 보임까지 각각 실제 초. 회차 380에서 15초 안에 못 주운 진짜 이유(늦게 나옴인지, 떨굼이 14m 밖·높이 차이로 멀었는지)도.
- 고칠 것: 시간은 사냥감이 죽은 순간부터 잰다(걸어가기 시작한 때 말고). 기다림 상한은 잰 숫자에 맞춘다(몸 있을 때 = 그 몹의 m_ttl + 잰 지연, 몸 사라진 뒤 = 잰 지연만큼). 떨굼이 몸 자리에서 멀리 떨어지는 게 원인이면 기다림 늘리지 말고 찾는 범위를 고친다. 15초·60초 상수는 없앤다.
- CullJob(솎기) PickLimit 20초도 같은 떨굼 기다림이라 같은 숫자로.
- 시험: vh_hunttest·vh_refilltest·솎기 시험 다시 PASS.
헛기다림 줄이기 4가지 (사용자 11-11, 묻지 말고 합리적으로 정해서 진행)
1) 상자가 열려 있을 때(Chests.InUse): 서서 기다리지 않는다. 넣기는 근처 다른 상자(빈 자리 있는 아무 상자)에 일단 넣고 나중에 정리 일(TidyJob)이 원래 상자로 옮긴다. 빼기는 같은 물건이 든 다른 상자에서 빼고, 없으면 다른 일 하다가 다시 온다. Unload BusyLimit 60초·CraftStep/FarmJob/MachineStep BusyLimit 30초·TidyJob EditWait 15초 대상.
2) 길들이기(TameJob) 지켜보기 WatchLimit 40초: 먹이 던진 뒤 그 자리에서 지켜보지 말고, 짐승 경보 범위(멧돼지 20m 등) 밖에서 간단한 채집·채광·사냥을 하다가 가끔 먹었는지 확인한다.
3) 동료 기다리기(Guard MateWait 30초): 부른 동료가 오기를 그만두면(그쪽 Guard 상태가 Come이 아님 — ComeLimit·막힘·부른 쪽 없음 등) 또는 오는 길이 막혔으면 그 순간 기다림을 접는다. 30초는 정말 오는 중일 때의 상한으로만.
4) 떨굼 주우러 걷기(GatherJob.Collect): WalledWait 10초(손 닿는 거리 단계 20초) 대신 다가가기와 같은 빠른 막힘 판정(Stuck: 거의 제자리 5초·1m도 못 가까워짐 MoveStuckLimit 10초)을 써서 막히면 바로 벽 확인·건너뛰기.
- 시험: 각 일 관련 게임 시험 다시 PASS(matetest·tame·farm·unload·tidy 등).
