사용자 → 무인 루프 요청 (밖에서 GitHub 앱·웹으로 이 파일을 고쳐 커밋한다)
- 요청 하나 = 한 덩어리. 첫 줄이 요청의 이름 역할을 한다. 덩어리 사이는 빈 줄.
- 요청 사이에는 빈 줄을 꼭 넣는다(붙여 써도 따로 보려고 하지만 빈 줄이 확실하다).
- 답은 history.md 맨 위에 "### 요청 · 날짜 · 이름"으로 온다: 회차는 시작하자마자 답부터 쓰고, 돌고 있는 회차가 있으면 15분 백업 때 확인해
  답 전용 세션이 15~30분 안에 답한다(질문은 바로 답, 일은 "[받음 시각]"을 앞에 붙여 두고 다음 회차가 맨 먼저 함). 가져간 요청은 루프가 이 파일에서 지운다.
- 루프가 멈춰 있으면(사용자 확인 필요·할 일 없음·진척 없음 등) 이 파일이 바뀌면 5분 안에 다시 돈다. 아주 멈추려면 loop-stop.txt를 만든다.
- 같은 걸 다시 시키려면 새로 쓴다(지워진 요청은 history.md에 남아 있다).
- 구분선 아래만 요청으로 읽는다.

시킨 일을 스스로 접지 말기(사용자 11-13 00:05)
- 밤: 탐험 중 밤이 되면 돌아오는 건 그대로, 하던 일은 기억했다가 날이 밝으면 다시 감(지금은 nightBack으로 일이 끝남).
- 습격: 일꾼이 습격 구역 안이고 거점에서 가까우면 지금처럼 귀환. 멀면(루프가 기준 정함) 그냥 하던 일 계속. 귀환해도 하던 일은 절대 안 잊음 — 지금 GoHome이 Job = null로 일을 지워 "일은 나중에"라고 해 놓고 까먹음(버그). 습격 끝나면 이어 감. 저장·재시작에도.
- 길 막힘(cantReach·stuck): 막힘 복구 순간이동은 지금 채집만 하고 사냥·탐험·지하묘지·동행은 안 함(decisions 막힘 복구 순서) → 사냥·탐험도 순간이동 복구를 쓰게(같은 안전 조건: 단단한 땅·위험 판단 통과·플레이어 보는 중 규칙). 그래도 안 되면 다음 줄.
- 포기 전에 셋 다: 일꾼 하나가 접는 까닭(못 닿음·못 찾음·너무 센 사냥감·무리·다침 반복 등)이면 바로 끝내지 말고 다른 일꾼, 그다음 호위병(또는 같이)까지 한 번씩 가 보고, 셋 다 안 될 때만 "못 하겠어" + 까닭. 연장·상자처럼 플레이어가 줘야 하는 까닭은 제외.
- 사냥감 2분 제한(HuntLimit): 고정 2분 대신 진척으로 — 사냥감 체력이 줄고 있으면 계속, 일정 시간(루프가 정함) 피해를 못 주거나 놓치면 다른 놈. 지금 2분 넘게 걸린 경우가 무엇인지(도망·물·절벽·약한 무기 등) 시험 기록에서 찾아 history에.
- 연장·활·화살이 없으면 스스로 만들기: noTool·needBow·toolBroke 때 플레이어한테 달라고 하기 전에, 필요한 제작대가 있으면 기존 제작 계획(재료 모으기 포함)으로 만들 수 있는 것 중 가장 좋은 것을 만들어 쓰고 이어 감. 제작대가 없거나 재료를 못 구할 때만 지금처럼 말함.
- 시험: 각 줄마다 — 밤에 끊긴 탐험이 아침에 이어짐, 습격 중 먼 일꾼은 계속·가까운 일꾼은 귀환 후 이어 감, 사냥 막힘 순간이동, 셋 차례 시도 후 포기, 연장 없이 시켜 만들어 쓰고 끝냄.
