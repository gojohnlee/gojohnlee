사용자 → 무인 루프 요청 (밖에서 GitHub 앱·웹으로 이 파일을 고쳐 커밋한다)
- 요청 하나 = 한 덩어리. 첫 줄이 요청의 이름 역할을 한다. 덩어리 사이는 빈 줄.
- 요청 사이에는 빈 줄을 꼭 넣는다(붙여 써도 따로 보려고 하지만 빈 줄이 확실하다).
- 답은 history.md 맨 위에 "### 요청 · 날짜 · 이름"으로 온다: 회차는 시작하자마자 답부터 쓰고, 돌고 있는 회차가 있으면 15분 백업 때 확인해
  답 전용 세션이 15~30분 안에 답한다(질문은 바로 답, 일은 "[받음 시각]"을 앞에 붙여 두고 다음 회차가 맨 먼저 함). 가져간 요청은 루프가 이 파일에서 지운다.
- 루프가 멈춰 있으면(사용자 확인 필요·할 일 없음·진척 없음 등) 이 파일이 바뀌면 5분 안에 다시 돈다. 아주 멈추려면 loop-stop.txt를 만든다.
- 같은 걸 다시 시키려면 새로 쓴다(지워진 요청은 history.md에 남아 있다).
- 구분선 아래만 요청으로 읽는다.

사냥·솎기 떨굼 기다림 줄이기 (15초·60초는 너무 김)
- 지금 GatherJob 사냥은 떨굼이 없으면 LootWait 15초, 쓰러진 몸이 있으면 LootWaitBody 60초까지 기다린다(회차 380). 떨굼은 길어야 2초쯤이면 나올 텐데 시간을 너무 먹는다.
- 바꿀 것: 시간은 사냥감이 죽은 순간부터 잰다(걸어가기 시작한 때 말고). 쓰러진 몸이 있는 동안만 기다리고(상한 = 실제 m_ttl + 1초쯤), 몸이 사라졌는데 떨굼이 없으면 2초 안에 그만두고 떠난다. 60초·15초는 없앤다.
- 먼저 확인: 멧돼지·사슴·목(Neck) 등 사냥감 Ragdoll 프리팹의 m_ttl 실제 값과, hunttest에서 죽은 뒤 떨굼이 나오기까지 실제 초를 로그에 찍어 history.md에 적는다. 회차 380에서 15초 안에 못 주운 진짜 이유(늦게 나옴인지, 떨굼이 14m 밖·높이 차이로 멀었는지)도 같이.
- CullJob(솎기) PickLimit 20초도 같은 떨굼 기다림이라 같은 기준으로 줄인다.
- 시험: vh_hunttest·vh_refilltest·솎기 시험 다시 PASS.
