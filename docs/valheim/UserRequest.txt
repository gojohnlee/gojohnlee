사용자 → 무인 루프 요청 (밖에서 GitHub 앱·웹으로 이 파일을 고쳐 커밋한다)
- 요청 하나 = 한 덩어리. 첫 줄이 요청의 이름 역할을 한다. 덩어리 사이는 빈 줄.
- 요청 사이에는 빈 줄을 꼭 넣는다(붙여 써도 따로 보려고 하지만 빈 줄이 확실하다).
- 답은 history.md 맨 위에 "### 요청 · 날짜 · 이름"으로 온다: 회차는 시작하자마자 답부터 쓰고, 돌고 있는 회차가 있으면 15분 백업 때 확인해
  답 전용 세션이 15~30분 안에 답한다(질문은 바로 답, 일은 "[받음 시각]"을 앞에 붙여 두고 다음 회차가 맨 먼저 함). 가져간 요청은 루프가 이 파일에서 지운다.
- 루프가 멈춰 있으면(사용자 확인 필요·할 일 없음·진척 없음 등) 이 파일이 바뀌면 5분 안에 다시 돈다. 아주 멈추려면 loop-stop.txt를 만든다.
- 같은 걸 다시 시키려면 새로 쓴다(지워진 요청은 history.md에 남아 있다).
- 구분선 아래만 요청으로 읽는다.

가축 고칠 것 3개 + 모든 종 길들이기 + 우리 얌전·문(사용자 11-10, 결함은 클라우드 세션이 코드로 확인)
1. 솎기: 종별로 세고 성체 최소 2마리(짝)는 늘 남김, 잡기 직전 남은 수 다시 셈. 성체 2+새끼 6이면 지금은 안 잡고 새끼가 자란 뒤 잡음. 근거 CullJob.Plan(우리 전체 수만 셈).
2. 데려오기 중 취소("그만"·집으로·따라와·급한 명령·쉬기·죽음)면 TameJob이 건 SetFollowTarget을 풂. WorkerAI의 Job = null 5곳이 정리 없이 지움 → 공통 정리 지점. 급한 명령으로 멈췄다 이어 하면 다시 겁. 따라오기가 남으면 Cullable에서도 영영 빠지는 문제 같이.
3. 모든 종 길들이기 완성: 늑대·록스·아스크스빈은 호위병 동행(위험 규칙대로). 닭·아스크스빈처럼 알로 늘어나는 종은 게임 DLL에서 야생 길들이기·알 부화 방식부터 확인(추측 금지). 무스는 게임에 없을 것(사슴 못 길들임 — DLL로 확인).
4. 우리 구별 = 상자 이름(사용자 결정): 상자 이름이 종 이름이면 그 종 우리 — 돼지·멧돼지·늑대·록스·닭·아스크스빈(영어 boar·pig·wolf·lox·chicken·hen·asksvin). 그 종만 길들여 데려오고, 그 상자 먹이를 그 종에게만 주고, 솎기도 그 종 기준. 일반 일은 이 상자에 손대지 않음(지금 "가축"처럼). "가축"은 그대로 두되 종은 넣은 먹이로 정함(맨 처음 들어온 종으로 굳음).
5. 우리 안 얌전하게: 우리 가축은 BaseAI.m_randomMoveRange를 2m쯤으로 줄여(인스턴스 값, 저장 안 됨 → 로드·데려오기 때마다 다시 걺) 상자 둘레에서만 어슬렁. 밖으로 밀려나간 건 쉴 때 데려오기로 되돌림. 효과는 시험으로 확인(추정).
6. 일꾼 드나들기: 플레이어가 울타리에 문 하나 → 먹이·솎기·풀어 두기 때 집 문처럼 열고 들어가 나오며 닫음. 지금 LivestockJob은 짐승 2m 앞까지 걸어가므로 벽이 있으면 막힘 — 문 길로.
7. 시험: 종마다 따로 칸(길들이기·데려오기·먹이·번식·솎기 짝 남김), 데려오다 "그만" 칸, 성체 2+새끼 6 칸, 늑대 우리인데 호위병 없으면 안 감 칸, 울타리+문 우리에서 10분 동안 탈출 0·일꾼 드나든 뒤 문 닫힘 칸. 멧돼지 시험 통과를 다른 종 완료 근거로 쓰지 않음.

안정성 고치기 + 채팅 "!" 없애기(사용자 11-10, 클라우드 세션 코드 리뷰)
1. Plugin.Update: 기능마다 따로 try. 한 기능 오류가 뒤 기능(WorkSaves·MorningSettle·SharedChests 등)을 멈추지 않게. 오류 로그는 기능별로 처음 한 번.
2. 시험 명령(vh_*test·vh_despawn): 시험 전용 월드·autotest 판이 아니면 실행 거절하고 이유를 콘솔에 표시.
3. 쓴 재료 다시 캐기 목록(Departures.s_debt): 일꾼 ZDO에 저장하고 월드 불러올 때 읽음. 다른 월드로 넘어가면 비움. Core 테스트 + 재시작 시험 칸.
4. 일 그만둘 때 정리: IWorkerJob에 정리(Cancel)와 잠깐 멈춤·이어 하기를 두고, WorkerAI의 Job 바뀌는 한 곳에서 늘 부름(Job = null 6곳·TidyJob 예외 처리 대신). 일마다 자기 것 정리 — TameJob 따라오기 풀기(가축 요청 2번은 이걸로), TidyJob 든 것 되돌리기, LivestockJob 꺼낸 먹이 되돌리기. 다른 일도 남기는 것이 있는지 하나씩 확인.
5. 채팅 "!" 없애기(사용자 결정: 인게임 채팅은 일꾼 명령 전용, 사람끼리는 디스코드): "!"가 없어도 정해진 명령은 모드가 먼저 바로 해석(Claude 안 거침), 못 알아들은 말만 Claude로. 일꾼 이름을 안 불러도 명령으로 봄. "!"를 붙인 옛 방식도 그대로 됨. 도움말·대사의 "!" 안내 고침. ChatParser 테스트 추가.
6. "그래도 가" 걷어내기(사용자: 그 시나리오는 이제 없음): 출발 전 질문 → "그래도 가" 대답 흐름이 실제 플레이에서 아직 나올 수 있는지 코드로 확인. 안 나오면 관련 코드(Departures.TestAutoGo와 시험 중 자동 대답, GoAnyway 명령·대사, 그 시험 칸)를 지움. 아직 나오는 질문이 있으면 지우지 말고 어떤 질문인지 history.md 답에 적음.

플레이용 빌드 표시 valheim-stable(사용자 11-10)
1. 태그 valheim-stable = 사용자가 직접 플레이할 빌드. 전체 게임 시험(회귀 묶음 전부)이 PASS한 커밋에만 옮긴다(git tag -f → push -f origin valheim-stable). 그 커밋의 valheim/dist DLL이 시험한 DLL과 같아야 함.
2. 언제: 요청·"다음"이 다 끝나 ALLDONE으로 끝내기 직전에 전체 회귀를 한 번 돌려 전부 PASS면 옮김. 하나라도 FAIL이면 옮기지 않고 Errors.txt 규칙대로. 회차마다 돌리지 않음(시간·토큰).
3. status.txt에 "플레이용 빌드: <커밋 해시7> <날짜> (전체 회귀 n/n)" 한 줄. 규칙은 loop-plan.txt·vh-loop-prompt.txt에, 받는 법(https://github.com/gojohnlee/gojohnlee/blob/valheim-stable/valheim/dist/ValheimHelper.dll)은 pc-howto.txt에.
4. 처음 한 번: 지금 valheim 맨 위로 전체 회귀를 돌려 PASS면 첫 태그.
