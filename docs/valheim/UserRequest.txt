사용자 → 무인 루프 요청 (밖에서 GitHub 앱·웹으로 이 파일을 고쳐 커밋한다)
- 요청 하나 = 한 덩어리. 첫 줄이 요청의 이름 역할을 한다. 덩어리 사이는 빈 줄.
- 요청 사이에는 빈 줄을 꼭 넣는다(붙여 써도 따로 보려고 하지만 빈 줄이 확실하다).
- 답은 history.md 맨 위에 "### 요청 · 날짜 · 이름"으로 온다: 회차는 시작하자마자 답부터 쓰고, 돌고 있는 회차가 있으면 15분 백업 때 확인해
  답 전용 세션이 15~30분 안에 답한다(질문은 바로 답, 일은 "[받음 시각]"을 앞에 붙여 두고 다음 회차가 맨 먼저 함). 가져간 요청은 루프가 이 파일에서 지운다.
- 루프가 멈춰 있으면(사용자 확인 필요·할 일 없음·진척 없음 등) 이 파일이 바뀌면 5분 안에 다시 돈다. 아주 멈추려면 loop-stop.txt를 만든다.
- 같은 걸 다시 시키려면 새로 쓴다(지워진 요청은 history.md에 남아 있다).

E083을 "시험 순서 탓"이 아니라 실플레이 버그로 다룬다(사용자 11-12)
- 일꾼은 결정 "자기 통나무 끝까지"(사용자 11-01)대로 굴러 온 반토막(beech_log_half)을 캐러 간 것 — 규칙은 맞음. 문제는 통나무가 집 벽·돌 바닥 가장자리(바닥 43.9, 땅 단차 0.6~0.7m)에 붙어 일꾼이 못 닿고 막힘·순간이동을 5~7번 되풀이한 것.
- 실플레이에선 집 가까운 나무를 베면 통나무가 집 쪽으로 구르는 일이 흔함 → 묶음 순서와 상관없이 재현 시험을 만든다: 통나무(반토막 포함)를 집 벽·바닥 가장자리·계단 밑·문 앞에 붙여 놓고 일꾼이 다 쪼개 가져오는지, 순간이동 0번인지.
- 닿을 수 있는 자리(바닥 위·땅 쪽·옆)를 골라 서서 치게 고치고, 정말 못 닿으면 되풀이하지 말고 건너뛰어 다음 일로(헛걸음 되풀이 금지) + 그 자리 diag.
- 순서: 지금 하던 재시작 시험(깃발 317→318 확인 포함) 다음.

나무 연쇄 쓰러짐 처리(사용자 11-12, 위 E083 요청과 함께)
- 쓰러지는 나무·구르는 통나무가 옆 나무를 치면 그 나무도 쓰러짐. 지금 코드는 일꾼이 직접 친 대상이 쓰러지거나 쪼개질 때만 그 자리를 기억(GatherJob.Approach NoteFelled) → 연쇄로 쓰러진 나무의 통나무는 첫 자리 15m 안에 떨어졌을 때만 우연히 챙김. 15m 밖으로 넘어간 것은 남는 것으로 보임(코드로 본 추정 — 시험으로 확인).
- 일꾼이 쓰러뜨린 나무·통나무에 맞아 쓰러진 나무(게임 코드로 연쇄 피해가 어떻게 전해지는지 DLL 확인 → codemap)도 "자기 통나무"로 기억해 끝까지 쪼개 가져온다.
- 같이 볼 것: OwnLog의 "건축물 4m 안 통나무 건너뜀"이 쓰러진 자리 19m 안 건물만 세어, 집에서 먼 곳에서 쓰러진 통나무가 집 곁으로 구르면 안 걸러짐(E083 목표가 집 바닥 곁 반토막). 집 곁 통나무를 칠지(집을 안 다치게 치는 방향) 건너뛸지 하나로 정하고 일관되게.
- 시험: 나무 빽빽한 곳에서 연쇄 쓰러짐 일부러 일으키기 → 통나무 0개 남음, 순간이동 0번, 집 조각 피해 0.

집 곁 통나무 결정(사용자 11-12): 일꾼이 치운다 — 건너뛰지 않음
- OwnLog·채집의 "건축물 4m 안 통나무 건너뜀"을 자기 통나무(연쇄 쓰러짐 포함)에는 적용하지 않는다. 집 곁·벽 곁·바닥 가장자리 통나무도 끝까지 쪼개 가져옴.
- 집이 안 다치게: 통나무를 집 반대쪽으로 밀리게 치는 자리에 서서 침(TreeLog.RPC_Damage는 hit.m_pushForce×2로 민다 — 맞는 방향 = 일꾼→통나무). 쪼갤 때 반토막·떨굼이 집 안으로 튀는지도 봄.
- 시험: 집 벽·돌 바닥 가장자리·계단 밑·문 앞에 통나무 붙여 두고 → 남은 통나무 0, 집 조각 체력 변화 0, 순간이동 0.
