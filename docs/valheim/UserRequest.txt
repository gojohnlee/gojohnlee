사용자 → 무인 루프 요청 (밖에서 GitHub 앱·웹으로 이 파일을 고쳐 커밋한다)
- 요청 하나 = 한 덩어리. 첫 줄이 요청의 이름 역할을 한다. 덩어리 사이는 빈 줄.
- 요청 사이에는 빈 줄을 꼭 넣는다(붙여 써도 따로 보려고 하지만 빈 줄이 확실하다).
- 답은 history.md 맨 위에 "### 요청 · 날짜 · 이름"으로 온다: 회차는 시작하자마자 답부터 쓰고, 돌고 있는 회차가 있으면 15분 백업 때 확인해
  답 전용 세션이 15~30분 안에 답한다(질문은 바로 답, 일은 "[받음 시각]"을 앞에 붙여 두고 다음 회차가 맨 먼저 함). 가져간 요청은 루프가 이 파일에서 지운다.
- 루프가 멈춰 있으면(사용자 확인 필요·할 일 없음·진척 없음 등) 이 파일이 바뀌면 5분 안에 다시 돈다. 아주 멈추려면 loop-stop.txt를 만든다.
- 같은 걸 다시 시키려면 새로 쓴다(지워진 요청은 history.md에 남아 있다).
- 구분선 아래만 요청으로 읽는다.

"!" 명령 띄어쓰기 무시
- "!라그나계속채워나무50", "!라그나 계속 채워 나무50"처럼 띄어쓰기가 달라도 같은 명령으로 받는다. 지금은 공백으로 나눈 뒤 맞지 않으면 Haiku로 넘어감(ChatParser.Split).
- 기본안: 정해진 꼴로 안 읽히면 공백을 다 빼고 앞에서부터 가장 긴 일꾼 이름 → 가장 긴 명령어(계속채워·채워·개인·끔·세트…) → 물건 이름·별칭 → 끝 숫자로 다시 읽는다. 그래도 안 되면 지금처럼 Haiku. Core에 넣고 dotnet test(띄어쓰기 변형·물건 이름에 숫자·이름이 겹치는 경우).

계속채워 현황 보기 (인게임)
- 1단계: "!계속채워"(뒤에 아무것도 없이) 또는 "!계속채워 목록" → 채팅에 항목마다 "나무 32/50 ■■■■■■□□□□" 꼴로 거점·개인 각각(개수는 RefillStock과 같은 셈).
- 2단계: 단축키(기본 F7, 설정으로 바꿈)로 여닫는 작은 창 — 항목마다 이름·현재/목표 숫자·게이지 막대, 모자란 것은 색으로. 열려 있을 때만 2초마다 다시 셈. 게임 화면을 가리지 않게 오른쪽 위, 마우스 없이 보기만.
- 게임 시험 하나(목록 대사·창 열림 로그 확인) 붙이기.

상자에서 계속채워 등록 (10-30 사용자 — 위 "계속채워 현황 보기"에 이어서)
- 상자 창에서 물건을 Alt+우클릭(기본안 — 그냥 우클릭은 바닐라 "쓰기"라 둠. 바닐라 InventoryGui 우클릭·Ctrl·Shift·Alt 처리를 DLL로 먼저 확인해 겹치지 않는 키로, codemap에 적기) → 그 물건을 거점 "계속채워"에 등록, 목표 수 = 지금 그 상자에 있는 수(0이면 한 묶음). 이미 있으면 같은 키로 끔. 일꾼 대사로 "나무 50개 계속 채울게" 확인.
- 개인 상자면 개인 계속채워로. 손님(친구)이 하면 호스트에 RPC로 부탁(Brain은 호스트) — SharedGuest 우클릭 막기와 겹치지 않게.
- 목표 수 바꾸기는 F7 창이나 채팅 "!계속채워 나무 80"으로. 순서: F7 창 → 상자 등록. 게임 시험 하나(등록·끄기·개인 상자).
