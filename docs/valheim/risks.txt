발헤임 일꾼 NPC — 위험 순위 (2026-10-21 검토, 상태는 2026-10-26 고침)
버그가 많이 나고 시간·토큰을 많이 먹을 순서. 일을 고를 때·계획을 줄일 때 본다. 상태: [시험됨] [진행 중] [안 짬] [보류]

1. 이동·길찾기 [시험됨, 계속 위험] — 구덩이·점프·물·먼 길 이동 생략·막힘 복구(R1·"오딘 구조" 옮기기) 있음, 늪(검은숲) 회귀 통과(회차 138~144).
   남은 큰 것: ⑬ 안개땅 절벽 — 지금 규칙으로 먼저 해 보고, 게임 갈고리(GrapplingPoint, codemap)는 그때 정함(사용자 10-24).
2. 작업 상태 저장 [시험됨] — 대기열·질문·하던 일을 ZDO에 저장, 실제 재시작 시험 vh_restart1→2 PASS(회차 98, 검은숲 회차 144).
3. ⑥ 제작 실행기 [시험됨] — vh_crafttest·portalbuildtest, 설비 소실 보충(회차 128).
4. 클라우드에서 짠 코드 묶음 [시험됨] — 출발 판단·장소 기억·스킬·세트·자동 보충·Claude 대답 모두 게임 시험 있음.
5. 멀티플레이(소유권·친구 채팅·동기화) [먼 구역·vh_peertest만] — 친구 접속 시험은 완성판에서(사용자 결정) → 아래 "혼자 하는 멀티 시험".
   주인 아닌 ZDO에 쓰던 곳 2개를 회귀에서 찾아 고침(회차 139·143) — 새 코드도 "손님 코드 규칙"(아래)대로.
6. 전투·위험(Guard) [시험됨] — 더 공격적으로·동료 부르기(10-24), 위험하면 덜 위험한 곳·둘이 같이(10-26, 게임 시험 대기). 방패 막기(10-26, 게임 시험 대기). 다음: 적 약점.
   기준이 바뀌면 싸움·습격·사망 시험 기대값을 다시 봄. 동료가 멀리서 오는 동행은 동료가 걸어서 와 느릴 수 있음(멀리선 이동 생략은 이끄는 쪽만).
7. ⑦ 철(지하묘지)·⑤ 포탈 [시험됨] — 묘지 안 길 찾기(회차 136), 바다 건너는 포탈로만(회차 137).
8. 무인 자동 루프(loop-plan.txt) [돌고 있음] — 남은 위험: 회차 도중 밖에서 푸시하면 회차 커밋이 rebase돼 기록 해시가 바뀜(회차 144 — 지시문에 다시 확인 넣음).
9. Claude 실제 호출 [vh_claudetest PASS] — 게임 안 호출과 무인 코딩 루프가 같은 Pro 한도를 나눠 씀.
10. 시험 동시 실행(최대 8명) [보류, 회차 34].
11. 농사 [시험됨] — 평탄화·길 만들기는 하지 않음(사용자 결정).
12. 바이옴 ⑪ 산 [끝] ⑫ 평원 [진행 중] ⑬ 안개땅 ⑭ 애쉬랜드 ⑮ 딥노스 [안 짬] — 딥노스는 내용을 모름(그때 게임 데이터로 확인).

혼자 하는 멀티 시험 (친구 접속 시험은 완성판에서만 — 사용자 결정 2026-10-21)
----------------------------------------------------------------------
바닐라 규칙(게임 1.0.20 디컴파일 확인, ZDOMan):
- 소유권 정리는 서버만 2초마다 한다(ZDOMan.Update → IsServer일 때 ReleaseZDOS). 호스트와 각 접속자 위치로 ReleaseNearbyZDOS.
- 주인이 있는 물체는 주인의 활동 영역 밖일 때만 다른 사람이 가져간다(IsInPeerActiveArea). 주인 peer가 없으면 영역 밖으로 침.
- FarZones가 ReleaseNearbyZDOS(호스트 것)·IsInPeerActiveArea를 패치해 NPC 주변(기준점)도 호스트 영역으로 셈
  → 바닐라 정리만으로는 친구가 NPC 소유권을 가져가지 않는 게 맞다. 위험은 다른 경로: 친구 게임에서 도는 이 모드 코드,
  ClaimOwnership 하는 바닐라 동작(상자 열기·줍기 등), 호스트에 인스턴스가 없는 물체(FindInstance null).

A. vh_peertest (게임 하나로, 매 회귀에 넣음)
  1) 소유권 뺏기: 일하는 중 / 상자 쓰는 중 / 싸우는 중 / 질문 기다리는 중마다 NPC ZDO를 없는 uid로 SetOwner.
     기대: 그동안 NPC가 ZDO·상자·인벤토리를 안 씀, 예외 0, 상자 잠금 풀림. 2초 안에 호스트가 되찾고(주인 peer 없음) 하던 일을 이어감,
     물건 총량 같음.
  2) 남의 채팅: Speaker를 가짜 이름·호스트에서 먼(인스턴스 없는) 캐릭터 ZDOID로 만들어 Commands.Handle.
     기대: 대답 받는 쪽·대기열·!같이 가자(따라갈 대상 인스턴스 없음)·!상자(대답만)가 예외 없이 처리되거나 이유를 말함.
  3) 손님 모드: 호스트가 아닌 것처럼(IsServer false 흉내 플래그) 모드 Update 경로를 돌려 아무것도 쓰지 않는지(친구 게임에서 도는 코드).
B. 코드 검사(토큰 적음, 한 번 하고 새 코드마다): 주인 아닐 때 ZDO·상자·인벤토리를 쓰는 곳, Player.m_localPlayer를 "말한 사람"으로 쓰는 곳,
   FindInstance가 호스트 근처에서만 되는 곳 목록 → 고침.
   빈틈(2026-10-21 확인): vh_peertest 1)은 주인 peer가 없는 경우(친구가 접속 끊음)만 흉내 → 2초 뒤 호스트가 되찾음.
   친구가 접속한 채 NPC 근처에서 주인이 되면 바닐라는 안 돌려줌(주인이 자기 영역 안). 혼자서는 시험 불가 → 코드로 막음:
   호스트가 NPC ZDO 주인을 1초마다 되찾음(Workers.Reclaim). 실제 확인은 C(같은 PC 전용 서버)나 완성판에서.
C. 단계마다 1번(③ 끝·⑥ 끝): 같은 PC에서 Steam 무료 도구 "Valheim Dedicated Server"를 켜고 사용자 게임이 127.0.0.1로 접속.
   사용자 게임이 진짜 "다른 컴퓨터"가 됨 → 말풍선·NPC 채팅·장비 표시·애니메이션 동기화, NPC 옆에 선 원격 플레이어, 원격 상자 열기.
   주의: 호스트가 화면 없는 전용 서버라 실제 구성(게임 안 "서버 시작")과 다름. Player.m_localPlayer·Chat·Minimap이 null인 경로가
   따로 터질 수 있다(어차피 막아야 할 것). 친구 실제 접속은 완성판에서.

작업 상태 저장 설계 (구현됨 — vh_restart1→2 PASS)
----------------------------------------------------------------------
- 대기열: QueuedWork의 람다 대신 데이터(종류, 물건, 수량, 말한 사람 이름, 급함, 고른 장소 구역, Ready 조건 종류: 없음/아침)를
  Core에 두고 ZDO "vh_queue"(NPC마다)에 저장. 불러올 때 데이터 → 작업 만들기. Core 테스트로 저장·불러오기 왕복.
- 질문 대기(Departures.s_pending): 질문 종류·대안 구역·조건 물건·물은 시각을 ZDO "vh_pending"에. 불러왔을 때 3분 넘었으면 보류 처리.
- 하던 일: 큰 단계만 저장(채집이면 물건·남은 수량·목표 구역). 세부 상태(다가가는 중 등)는 처음부터 다시 해도 되게.
- ⑥ 실행기: 단계 DAG와 끝난 단계 표시를 저장. 설비 Wait는 설비 ZDO가 시간을 가지므로 다시 읽어 이어감.
- 시험: vh_departtest 끝에 "저장 → NPC 다시 불러오기 → 대기열·질문 그대로" 확인.

손님(멀티) 코드 규칙 — 이후 기능이 따를 것 (루프 회차 42 코드 검사 결과, 2026-10-22)
----------------------------------------------------------------------
검사: Plugin의 모든 Harmony 패치·Plugin.Update 정적 틱·WorkerNpc/WorkerAI·채팅 경로. 고칠 곳 없음(회차 35 수정 포함 전부 규칙을 지킴).
1. 정적 틱(Plugin.Update에서 부르는 것)은 ZNet.instance.IsServer()가 아니면 ZDO·상자·인벤토리에 쓰지 않는다(Workers·Departures·Brain·WorkSaves·MapSense·FarZones 이미 지킴). 새 틱도 맨 앞에 같은 확인.
2. NPC에 쓰는 코드는 m_nview.IsOwner()일 때만(WorkerAI.UpdateAI는 바닐라 BaseAI가 주인 아니면 false). 상자는 TryEdit(소유권), 설비는 RPC. 소유권을 직접 SetOwner 하는 건 Workers.Reclaim(호스트)뿐.
3. 채팅은 손님이 VH_Chat RPC로 보내고 호스트(RPC_Chat, IsServer 확인)만 Commands.Handle. 말한 사람은 sender peer로 찾고 Player.m_localPlayer는 호스트 자신(peer 없음)일 때만 쓴다. 새 명령도 Commands.Handle 안에서만.
4. 손님 PC에서 도는 패치는 전부 읽기·막기뿐(WearNTear.Damage는 일꾼 공격 막기, RPC_Damage 갑옷 계산, NoDig는 WorkerNpc일 때만 — Attack은 주인 게임에서만 돈다). 새 패치가 지형·ZDO를 바꾸면 안 됨.
5. Player.m_localPlayer·Minimap·Chat은 전용 서버에서 null일 수 있으니 null 확인 후 쓴다. 화면 표시(말풍선 VH_Say)는 Everybody로 보내 각자 그린다.
