# PC 실행 지시: Claude 구현 → Astra 검증 무인 루프 통합

작성일: 2026-10-26 (한국 시간). 사용자가 PC의 ChatGPT Work에서 이 문서를 읽고 실행하도록 요청할 때 적용한다.
이 문서를 올리는 것 자체는 루프 재개 지시가 아니다. 멈춤 파일은 그대로 둔다.

## 실행 요청

이 저장소의 최신 무인 루프와 합의 문서를 읽고, Claude 구현 → 로컬 Codex Astra 검증 분업을 구현·연결·검증한다.
사용자는 Astra 호출이 가능하다고 확인했다. 검증 모델은 Astra이며 임의로 가벼운 모델로 바꾸지 않는다.
실제 CLI 모델 식별자·호출 방법은 PC의 설정과 실행 결과로 확인하고 추측해서 넣지 않는다.
ChatGPT는 Plus로 알려져 있으나 PC 로그인 상태는 직접 확인한다. 로그인이나 권한이 필요한 경우에만 사용자에게 구체적으로 요청한다.
이 통합 구현은 PC의 GPT 작업자가 시작해도 된다. 통합 이후 모드 개발에서는 Claude가 구현하고 Astra는 검증한다.

## 먼저 확인

- CLAUDE.md 및 존재하는 AGENTS.md, docs/valheim/decisions.txt의 2절 GPT 검증 분업, progress.txt의 지금·다음, Errors.txt.
- docs/valheim/loop-plan.txt, scripts/vh-loop.ps1, vh-loop-prompt.txt, vh-reply-prompt.txt, vh-loop-restart.ps1, valheim-test.ps1.
- 현재 브랜치·HEAD·로컬 미커밋 변경·stash·실행 중인 루프/작업자/게임. 기존 작업을 덮어쓰거나 버리지 않는다.
- 동일한 통합 작업을 다른 세션이 시작했는지 확인한다. 수정 주체는 한 명이며, 기존 회차를 안전하게 마친 뒤 넘겨받는다.
- 로컬 명령 실행과 저장소·게임 경로 접근 여부를 실제로 확인한다. GitHub 연결만 가능하면 PC 실행 시험까지 했다고 보고하지 않는다.

## 구현 순서

1. 기존 합의대로 Claude 회차별 입력·출력·캐시 사용량, 턴 수, 경과 시간을 기록한다. 실제 출력에 없는 수치는 지어내지 않고 미확인으로 남긴다. 답 전용 세션은 별도로 구분한다.
2. progress.txt 순서대로 기존 변경분 게임 시험과 호위병 작업을 진행하며 기준 5~10회차를 모은다. 최신 문서가 정한 진입 조건을 따른다. 횟수만으로 절약 효과를 단정하지 않는다.
3. Claude가 구현·시험 코드를 작성하고 빌드·Core 테스트를 통과한 커밋과 필요한 게임 시험 목록을 인계하도록 연결한다.
4. 루프 스크립트가 게임 시험을 실행하고 결과·원본 로그를 보존한다. 시험 대상 커밋과 실행한 DLL의 대응을 확인한다. 환경 불량·중도 종료·누락된 결과를 PASS로 취급하지 않는다.
5. Astra는 해당 커밋의 diff와 관련 코드, 시험 조건·기대값을 리뷰하고 FAIL 원인을 분석한다. 검증 중 Claude는 다음 코드 수정을 하지 않는다.
6. 실패는 재현 조건·기대 결과·실제 결과·파일 위치·로그 근거를 Claude에 넘긴다. Claude 수정 후 다시 검증한다. 구현과 검증을 한 논리 회차로 묶어 진척·연속 FAIL·무진척 중단 규칙을 유지한다.
7. Astra 한도나 오류 시 기존 Claude 구현·시험·수정 방식으로 복귀한다. 확정된 차단 결함은 넘기지 않고 비차단 항목은 진행한다. 모든 실행 대상이 사용 불가일 때 기존 대기·깨우기 정책을 적용한다.
8. 유사한 작업 종류끼리 분업 전후의 Claude 사용량·회차 시간·재작업을 비교하고 history.md에 보고한다.

## 검증 규칙

- 최신 decisions.txt와 사용자 요구가 기준이다. 사용자 결정을 바꾸자는 의견은 결함과 구분한다.
- 코드로 확인한 사실, 실행으로 재현한 사실, 미확인 가설을 구분한다. 게임 내부 동작에 의존하는 주장은 실제 게임 코드 또는 확인된 근거를 확인한다.
- 복제·소실·저장 손상·복원 실패뿐 아니라 명령 불이행, 무한 반복, 수량 미달 완료, 잘못된 시험 기대값도 검토한다. 스타일 지적은 제외한다.
- Astra가 제안한 재현 조건·기대 결과도 요구사항에 비추어 검토 대상이다. 근거 있는 반박을 허용한다. 모델의 승인 자체를 증거로 삼지 않는다.
- 가설만으로 루프를 막지 않는다. 확정된 차단 문제는 모델 한도와 무관하게 유지한다.
- 검증자는 본체 코드를 수정하지 않는다. 검증 전 상태와 후 상태를 비교해 허용한 결과 파일 외 변경을 감지한다. 기존 미완성 변경을 무조건 reset/clean으로 지우지 않는다. 위반 시 증거와 변경을 보존하고 검증을 무효 처리한다.
- 테스트 실패 원본 로그는 재실행 전에 보존한다. 재실행 PASS만으로 처음 FAIL을 없애지 않는다.
- 한도·인증 오류·일반 실행 실패·시간 초과를 구분한다. 실제 Codex 출력과 종료 동작으로 처리하며 미확인 한도 해제 시각을 지어내지 않는다.
- 회차 사이 재시작에도 인계 커밋·단계·결과가 보존되고 중복 작업이 발생하지 않게 한다.

## 완료 확인과 보고

- PowerShell 문법과 기존 BOM 등 실행 조건을 확인한다.
- PC에서 한 회차의 인계→시험→검증→결과 기록을 확인한다. 실패 반환·Codex 사용 불가 시 복귀 경로는 통제된 모의 실패로도 검증하되 실제 한도 시험과 구분해 기록한다.
- 진행 중 사용자 작업·실제 플레이 월드에 영향을 주지 않고 기존 전용 시험 환경을 사용한다.
- 구현·검증한 커밋, 시험 결과, 남은 미확인 사항을 history.md와 progress.txt에 기존 형식으로 남긴다. 클라우드 컴파일이나 모의 시험을 실제 게임 PASS로 바꾸어 적지 않는다.
- 기준 측정이 아직 부족하면 측정 및 기존 작업을 이어갈 수 있게 만들고, 분업 도입 조건과 다음 할 일을 남긴다. 미구현 단계는 완료라고 하지 않는다.
- 루프 재개는 사용자가 PC에서 실행을 지시한 범위에 맞춰 처리한다. 이 문서 등록만으로 stop 파일을 삭제하거나 루프를 재개하지 않는다.
