발헤임 일꾼 NPC — 진행 상황 (세션이 끊겨도 여기서 이어간다)

이 파일은 "지금 상태 + 남은 일 순서"만 둔다(사용자 결정 10-24: 끝난 일은 history.md에 있으니 여기서 지움). 옛 전체본은 git 커밋 a01aaee의 이 파일.
읽는 순서(토큰 아끼기, 2026-10-21 사용자 결정)
- 새 세션: 이 파일 → 필요한 코드만 codemap.txt로 찾아 읽기. 구상서(concept-v1.txt)·설계서(design-depart-craft.txt)는 그 장만. 결정은 decisions.txt(grep).
- 지난 기록(시험 결과·원인 분석·예전 결정 전체)은 history.md — 평소엔 읽지 않고 필요할 때 grep.
- 파일은 통째로 읽지 말고 grep으로 찾은 부분만. 게임 코드 확인 결과는 codemap.txt "확인된 게임 사실"에 적어 두고 다시 디컴파일하지 않는다.
- 15분마다(빌드·테스트 통과 때마다) 커밋·푸시하고 이 파일의 "지금"과 "다음"만 고친다. 끝낸 일 기록은 history.md 맨 위 "회차 기록"에
  bash scripts/vh-history-add.sh로 넣고(history.md는 읽지 않음), "지금"에는 같은 요약을 맨 위에 넣고 최근 3개만 둔다(넘친 것은 지움 — history에 이미 있음).
- "다음" 정리(사용자 결정 10-24): 조각을 끝내면 그 줄을 "[끝, 회차 N — 커밋 · 시험]" 한 줄로 줄인다. ★ 덩어리의 조각이 전부 [끝]이면
  다음 회차가 시작할 때 덩어리째 지운다(같은 회차에 지우면 루프가 [끝] 줄을 못 봐 진척으로 안 셈). 덩어리 머리는 "★ 이름 (근거)", 조각은 "  가) …" 꼴로
  — status.txt "할 일"이 "다음"의 첫 안 끝난 ★와 그 첫 안 끝난 조각을 보여 준다(scripts/vh-loop.ps1 Write-Status).

PC 세션 시작 순서 (사용자 PC: Windows, 게임 설치됨, 호스트)
======================================================================
1. git checkout valheim (발헤임 작업은 이 브랜치에만, 푸시도 valheim으로 — 사용자 승인).
2. 도구: git, dotnet(.NET SDK 10), ilspycmd(dotnet tool install -g ilspycmd). 없으면 사용자에게 설치 부탁(winget).
3. 게임 DLL: C:\Program Files (x86)\Steam\steamapps\common\Valheim\valheim_Data\Managed (csproj가 자동으로 찾음, 다르면 -p:ValheimRefs=<폴더>).
   게임 코드 읽기: ilspycmd -p -o <임시폴더> "<Managed>\assembly_valheim.dll" (저장소에 올리지 않음).
4. 빌드: Git Bash에서 ./scripts/valheim-build.sh (빌드 + 게임 Mono에 없는 참조 검사 + valheim/dist 복사). Core 테스트: dotnet test valheim/ValheimHelper/ValheimHelper.slnx
5. 게임 시험(손 안 댐), PowerShell:
   $env:VH_DLL="<저장소>\valheim\ValheimHelper\Plugin\bin\Release\ValheimHelper.dll"; $s=[IO.File]::ReadAllText("<저장소>\scripts\valheim-test.ps1",[Text.Encoding]::UTF8); & ([scriptblock]::Create($s))
   (-File은 PowerShell 5.1이 BOM 없는 UTF-8 한글을 깨뜨림. 이 PC엔 파이썬 없음 → 수정은 Edit 도구. git 이름은 저장소 설정 Claude <noreply@anthropic.com>.)
   설치 → Steam 실행 → 인트로 건너뜀 → te4st41 자동 입장 → 시험 → 2초 뒤 종료 → 결과 출력.
   시험 고르기 $env:VH_TEST="vh_npctest;vh_flagtest;vh_woodtest;vh_stonetest"(기본). 그 밖에 vh_preptest·vh_bagtest·vh_deathtest·vh_fighttest·vh_exploretest·
   vh_pittest·vh_coppertest·vh_fartest·vh_departtest·vh_peertest(묶음 1), vh_portaltest·vh_portalbuildtest·vh_tintest·vh_stucktest·vh_hoptest·vh_skiptest(멀리선 이동 생략)·vh_resisttest·vh_repairtest·vh_crypttest·vh_hunttest·vh_cooktest·vh_cookwettest(비바람)·vh_farmtest·vh_basetest(기반 대표)·vh_escorttest(동행)·vh_mychesttest(개인 상자 준비)·vh_sharetest(상자 손님 부탁 호스트 쪽)·vh_guesttest(손님 화면 옮기기, 가짜 손님). 실제 재시작: VH_TEST=vh_restart1(되돌리기 켜고, 끝에 바로 꺼짐) 다음 VH_RESET=0·VH_TEST=vh_restart2. 월드 $env:VH_WORLD. 시험 캐릭터는 전용 vhtest(없으면 모드가 만듦), 실행마다 시험 월드를 원본(%USERPROFILE%/vh-test-base, 첫 실행 때 뜸)으로 되돌림 — 끄기 $env:VH_RESET="0"(재시작 시험 2번째 실행). 기본은 연속 묶음(한 번 되돌리고 이어 돌림), 약식(긴 시험 짧게) $env:VH_QUICK="1", 깨끗한 단독 시험은 $env:VH_SOLO="1"(시험마다 되돌리고 게임 새로 켬, 시험별 diag-<시험>.txt). 항상 최소화·소리 끔이 기본(사용자 2026-10-21), 화면 보려면 $env:VH_MIN='0'.
   결과: 스크립트는 짧은 요약만 출력(diag 첫 줄, 시험별 판정·시간, FAIL 줄, 로그 오류 종류 8개 — 2026-10-21 토큰 절약).
   전체는 <게임>\BepInEx\plugins\ValheimHelper\diag.txt(FAIL이면 그 시험 '=== 이름' 부분만 grep), 오류 <게임>\BepInEx\LogOutput.log.
   게임이 사용자 화면에서 켜짐 → 시작 전에 한 번 묻는다.
6. dist DLL도 커밋(방식 A 한 줄 명령이 valheim/dist를 받음).
클라우드 세션: 환경 네트워크에 nuget.bepinex.dev 허용됨(2026-10-23) → valheim-refs clone 뒤 bash scripts/valheim-build.sh로 빌드 확인 가능(ilspycmd는 dotnet tool install -g ilspycmd).
  게임 시험은 PC만. 클라우드에 dotnet이 없으면 dot.net/v1/dotnet-install.sh --channel 8.0 → ilspycmd --version 8.2.0.7535, 실행 때 DOTNET_ROLL_FORWARD=Major(10-24 확인).
  클라우드에서 만든 dist DLL은 커밋하지 않음(시험한 PC 빌드가 기준).
