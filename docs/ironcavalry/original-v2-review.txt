RimWorld 1.7 기획서 v2 재검토 결과

검토 대상: RimWorld_1.7_철기병_메카관리_기획서_v2.txt
검토 범위: 문서 내부의 일관성, 행동 전환, 성능 제약, 구현자가 다르게 해석할 수 있는 규칙.
이번 검토에서는 실제 RimWorld 1.7 DLL·기존 모드 코드·게임 실행 결과를 확인하지 않았다.
아래 내용은 수정 제안이며, 원본 v2 기획서는 변경하지 않았다.

유지할 사용자 확정 사항
- 자동 후퇴·돌격 판단 및 재사용 대기: 900게임틱.
- 철기병의 후퇴 목적지는 현재 공격 대상과 주변 후보만으로 판단.
- 소탕 중에도 자동 후퇴·돌격 사용 허용.
- 소탕 검사: 54,000게임틱마다 한 번.
- 소탕 출동 전력: 20% 이상.
- 전력 10% 이하에서는 소탕에서만 이탈. 귀환 전력 예측과 강제 충전 복귀는 추가하지 않음.
- 위험하다는 이유만으로 지정 절전 자리 복귀를 거부하지 않음.
- 새 기능이나 외부 의존성을 늘리는 방식으로 문제를 해결하지 않음.

1. 우선 수정: 목표와의 간격과 실제 돌격 이동 거리의 혼용
관련: A5 196~214행, A8 265~269행.

문제:
피해는 실제 접근 거리 3~8칸으로 결정되지만, 후퇴 목표는 적과의 간격 3~8칸으로 표현되어 있다.
근접 공격은 표적의 칸에 들어가기 전에 발생한다. 예를 들어 인접 1칸에서 공격한다면 8칸 떨어진 위치에서 출발해도 실제 달리는 거리는 약 7칸이다.
문서대로 구현했는데 최대 강화가 나오지 않거나 최소 거리에서 강화되지 않을 수 있다.

수정 방향:
- 실제 달린 유효 접근 거리와 표적과의 간격을 다른 값으로 정의한다.
- 후퇴 목표 간격은 원하는 유효 접근 거리와 실제 근접 공격 도달 거리를 함께 고려한다.
- 후퇴 후보를 찾는 범위는 현재 자기 위치 기준 최대 8칸을 유지한다.
- 거리 단위와 대각선 처리 방식을 한 곳에서 정의한다.
- 정지 표적 대상으로 정확히 최소 강화와 최대 강화가 나오는 배치 검증을 추가한다.

2. 우선 수정: 움직이는 표적과 왕복 이동의 충전 계산
관련: A5 214행, A7 237~243행.

문제:
"실제 접근", "움직이는 대상 고려", "왕복 악용 금지"는 있지만 계산 규칙은 없다.
거리 변화만 사용하면 적이 다가온 만큼을 충전하거나, 양수 접근량만 더하면 왕복으로 충전할 수 있다.

수정 방향:
- 실제 철기병의 위치가 변한 경우에만 충전 계산을 수행한다.
- 한 이동의 전후를 비교할 때는 동일한 표적 위치를 기준으로 해 표적 자체의 이동량을 제외한다.
- 멀어지는 이동은 순접근량에서 차감하거나 돌격을 취소하도록 규칙을 하나로 고정한다.
- 초기 기본안은 순접근량 차감이다. 음수 부분을 즉시 버리고 양수만 누적하는 방식은 금지한다.
- 큰 방향 전환/우회의 취소 기준도 수치 또는 명확한 판정으로 작성한다.
- 실제 적용 피해는 최종 유효 접근량을 0~8칸으로 제한해 계산한다.
- 표적만 이동, 자기 왕복, 대각선, 표적 사망과 이동을 별도로 검증한다.

3. 우선 수정: 돌격 자체의 지속 시간 및 중복 시작 방지
관련: A7 257행, A8 265행·280~290행.

문제:
180틱 제한은 후퇴에만 있다. 먼 표적이나 도망가는 표적을 상대로 돌격 속도 1.5배가 장시간 유지될 수 있다.
900틱 쿨다운이 끝났을 때 아직 기존 돌격 중이라면 새 돌격을 시작하지 말라는 명시도 필요하다.

수정 방향:
- 후퇴 중/돌격 중에는 새 자동 후퇴·돌격을 시작하지 않는다.
- 실제 돌격에도 유한한 제한 시간을 정한다. 구체 수치는 기본 이동속도와 정상 돌격 소요 시간을 확인해 초기 밸런스 표에 기록한다.
- 지나치게 먼 대상에는 일반 접근을 먼저 수행하고, 유효한 돌격 시작 조건에서 속도 보너스를 부여한다.
- 제한 시간 초과/대상 소멸 시 일반 전투로 복귀하고 속도와 충전 상태를 정리한다.
- 취소로 이미 시작한 돌격 쿨다운을 환급하지 않는다.
- 8칸 피해 상한은 돌격 시간 상한과 별개다.

4. 우선 수정: 억제한 옛 위협이 새로운 비상의 자동 해제를 막는 문제
관련: B3 407~429행·455~461행.

재현:
1) 비활성 군집 A 때문에 비상이 켜짐.
2) 사용자가 해제하여 A를 억제함.
3) 새 습격 B로 비상이 다시 켜짐.
4) B를 해결했지만 A는 그대로 남아 있음.
5) "모든 미해결 위협이 없어야 해제"로만 구현하면 자동 해제되지 않음.

수정 방향:
- 현재 비상 유지 조건을 "수동 유지 상태 또는 억제되지 않은 미해결 위협이 존재함"으로 정의한다.
- A가 억제 상태를 유지한다면 B 해결 후 자동 비상을 해제한다.
- A가 활성화되는 등 새 위험 단계로 바뀌었다면 A는 다시 비상 유지 원인이 된다.
- 수동으로 켠 상태는 다른 위협의 등장/해결로 자동 해제하지 않는다.
- 위 시나리오를 저장·불러오기까지 포함해 검증한다.

5. 우선 수정: 비상 상태가 계속 켜져 있을 때 소탕 재시작 금지
관련: B4 523~532행·590행.

문제:
현재 참여 조건은 개체가 "대피·집결 중이 아님"이고, 중단은 "비상 발생" 시점 기준이다.
집결 이동이 끝났거나 비상 역할에 체크되지 않은 메카가 비상 유지 중 다음 소탕에 출동할 수 있다.

수정 방향:
- 맵의 비상 상태가 활성화되어 있으면 새로운 자동 소탕 실행을 시작하지 않는다.
- 기존 소탕은 비상 전환 시 중단한다.
- 집결 도착 여부와 맵의 비상 유지 여부를 다른 상태로 관리한다.
- 비상 중 검사 시점이 오면 그 회차를 건너뛰고 다음 54,000틱 시점을 예약한다.
- 비상 해제 직후 소탕을 즉시 시작할지의 불명확함은 없앤다. 최소 변경 기본안은 다음 정기 회차까지 대기하는 것이다.

6. 우선 수정: 집결 도착 후 전투 대기와 절전 복귀의 충돌
관련: B2 373~378행, B3 491~500행.

문제:
절전 중인 전투 메카를 깨워 이동시키는 규칙은 있지만, 도착 후에도 비상이 지속될 때의 상태는 불명확하다.
이동 작업만 끝내면 기존 자동절전 모드가 다시 재워 버리거나 평상시 작업으로 돌아갈 수 있다.

수정 방향:
- 비상 활성 중 집결 대상으로 지정된 전투 메카는 교전 가능한 전투 대기 상태를 유지한다.
- 그 상태에서는 기존 자동절전 시작을 억제하되, 실제 전투 AI와 사용자 직접 명령은 막지 않는다.
- 모드가 변경한 전투/작업/징집 상태만 저장하고, 종료 시 사용자 변경 여부를 확인해 복원한다.
- 집결 명령을 반복해서 강제로 내리는 방식으로 전투 대기를 구현하지 않는다.
- 위협 감지 대상과 공격 명령 대상을 분리한다. 비활성 군집의 존재로 비상이 켜졌다고 그 군집을 공격 대상으로 지정하지 않는다.
- 평상시 위험한 절전 자리로 돌아가는 규칙은 유지한다. 이 수정은 비상 중의 우선순위만 명확히 한다.

7. 수정 권장: 직접 명령의 예외와 권한 수명
관련: 공통 규칙 107~108행, A4 188~189행, B4 556행.

문제:
공통 규칙은 직접 명령 중 자동 행동 배정을 제외하지만, 철기병은 수동 근접 공격 대상을 유지하며 자동 후퇴·돌격을 사용할 수 있다.
현재 작업 객체만으로 직접 명령 여부를 판정하면 내부 후퇴 작업으로 바뀐 순간 사용자 명령의 우선권을 잃을 수 있다.

수정 방향:
- 수동 근접 공격의 같은 대상을 유지하는 내부 후퇴·돌격은 공통 금지의 예외라고 명시한다.
- 내부 행동을 교체해도 원래 수동 공격의 대상과 우선권은 유지한다.
- 다른 직접 명령, 대상 무효화, 공격 명령 종료 시 해당 의도를 정리한다.
- 소탕 내부 후퇴는 새 수동 명령으로 취급하지 않는다.
- 소탕 중 실제 사용자 명령은 참여 이탈 조건으로 유지한다.

8. 수정 권장: 두 모드의 선택적 연결 방식 명시
관련: 독립성 65~71행, A3 170~175행, B4 548~555행.

문제:
두 모드는 각각 단독 실행해야 하지만, 관리 모드는 철기병이 공유 대상을 유지한 채 후퇴·돌격 중임을 알아야 한다.
서로의 DLL을 필수 참조하거나 내부 작업을 강제로 교체하는 방식이면 단독 로딩 또는 행동 연동이 깨질 수 있다.

수정 방향:
- 상대 모드가 없는 경우에도 필수 타입 로딩이나 Def 참조 오류가 없어야 한다.
- 함께 설치된 경우 공유 대상, 행동 소유자, 행동 종료/취소를 주고받는 최소한의 선택적 연결 규칙을 정의한다.
- 별도 공용 라이브러리를 새 의존성으로 요구하지 않는다.
- 선택적 연동 검색은 로딩/초기화 시 수행하고, 매 틱 리플렉션이나 Def 전체 검색을 하지 않는다.
- 단독 두 경우와 병용 한 경우의 로딩·기본 전투·소탕 연동을 각각 확인한다.

9. 수정 권장: 정기 소탕 검사와 대상 목록의 수명
관련: B4 505~512행·537~544행·592행, D 665~666행.

문제:
기존 소탕이 진행 중이면 다음 검사를 건너뛴다고만 쓰면, 만료된 타이머를 갱신하지 않아 매 틱 다시 검사하는 구현이 나올 수 있다.
한 마리 처치할 때마다 새 대상 검색을 위해 전체 동물 목록을 재조회하는 것도 현재 문서로는 명확하게 금지되지 않는다.

수정 방향:
- 54,000틱 회차마다 다음 검사 시각을 확실히 갱신한다. 비상/소탕 진행으로 건너뛴 경우도 동일하다.
- 검사 시 얻은 대상 목록을 해당 소탕 실행의 후보 목록으로 사용한다.
- 다음 대상 선택은 그 목록 안에서 하고, 대상의 현재 생존·소유권·접근 가능 여부만 필요한 순간 재확인한다.
- 이후 새로 들어온 동물은 다음 정기 회차 대상에 넣는다.
- 접근 실패·소유권 변경·이탈 등으로 제외된 후보는 같은 실행에서 무한 재선택하지 않는다.
- 참여자와 후보 목록을 저장하거나 일관되게 재구성해 불러오기 직후 중복 소탕을 만들지 않는다.

10. 수정 권장: 비상 진행 중 대상 체크·직접 명령 종료·구역 변경
관련: 공통 규칙 106~108행, B3 465~488행.

문제:
대피 적용이 비상 시작 시점에만 묶이면, 비상 중 새로 체크한 개체나 직접 명령을 끝낸 개체는 다음 비상까지 방치될 수 있다.
개체의 활동구역을 사용자가 직접 바꿨는데 재확인 로직이 다시 안전구역을 적용하는 문제도 가능하다.

수정 방향:
- 비상 중 대피 대상으로 새로 체크한 개체는 현재 구역을 한 번 저장하고 즉시 대피 적용한다.
- 직접 명령 때문에 보류한 대피는 그 명령이 끝나도 비상이 유지 중이면 재개한다.
- 사용자가 개체 활동구역을 직접 바꿨다면 해당 비상 동안 다시 덮어쓰지 않고 종료 시에도 자동 복원하지 않는다.
- 공통 안전구역을 바꾸거나 삭제한 경우에는 비상 종료 시까지 기다리지 않고 그 변경 시점에 처리한다.
- 체크/UI 변경, 작업 종료 등 상태 전환 지점에서 처리하고 매 틱 전체 대피 대상을 다시 순회하지 않는다.
- 첫 비상 진입과 진행 중 편집의 원래 구역 저장 규칙을 동일한 상태 관리에서 처리한다.

11. 수정 권장: 절전 자리 이동 실패 뒤 기존 절전을 재차 가로채는 반복
관련: B2 348~354행·367~368행.

재현:
1) 기존 모드가 절전을 시작함.
2) 새 모드가 배정 자리 이동으로 전환함.
3) 접근 실패 후 기존 절전으로 복귀함.
4) 새 모드가 그 절전 시작도 다시 자리 이동으로 바꿈.
5) 같은 실패가 반복됨.

수정 방향:
- 한 번의 절전 전환에서 자리 이동은 한 번만 시도한다.
- 실패 후에는 해당 절전 전환에 우회 표시를 두어 기존 절전을 그대로 허용한다.
- 다음 정상적인 기상/절전 전환이나 사용자 자리 재배정 시에만 다시 시도한다.
- 파괴된 자리 참조를 정리한다.
- 한 자리의 배정은 한 메카를 기본으로 하고, 재배정할 때 이전 연결을 정리해 예약 경쟁을 줄인다.
- 기존 자동절전 모드의 실제 시작 지점을 확인한 뒤 구현한다. 현재 단계에서 특정 API가 존재한다고 가정하지 않는다.

문서 편집 방향
- 새 규칙을 계속 뒤에 덧붙이기보다 기존 모호한 문장을 교체한다.
- 동일 타이밍/상태 규칙은 한 곳에서 정의하고 검증 목록에서는 그 규칙을 참조한다.
- 사용자 확정 사항과 이번 검토의 구현 기본안·미확정 세부 수치는 구분한다.
- 900틱, 로컬 후보 5개, 10% 단순 이탈 자체를 더 무겁게 바꿀 이유는 이번 검토에서 발견되지 않았다.
- 실제 1.7 API나 기존 절전 모드와의 호환성은 환경 조사 후 별도 검증이 필요하다.
