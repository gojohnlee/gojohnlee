RimWorld 1.7 — 철기병 및 메카 관리 모드 제작 명세

0. 작업 지침

이 문서는 기획서이자 구현·검증 기준이다. 사용자는 실제 설치 가능한 모드를 원한다.

- 대상 게임은 RimWorld 1.7이다.
- 사용자는 모든 DLC를 보유한다.
- Harmony와 모드 자체 C# DLL은 허용한다.
- 그 외 외부 프레임워크·라이브러리를 필수로 요구하지 않는다.
- Combat Extended는 사용하지 않는다.
- 실제 1.7 게임 DLL, XML Def, 설치된 모드를 확인하고 구현한다.
- 확인하지 않은 클래스·메서드·Def 이름을 추측해서 사용하지 않는다.
- 이 문서의 기능·우선순위·예외 처리를 먼저 읽고 구현한다.
- 빌드 성공과 게임 내 정상 작동 검증을 구분한다.
- 실제 수행하지 않은 테스트나 성능 측정은 완료했다고 보고하지 않는다.
- 파일을 확인하면 알 수 있는 내용은 사용자에게 다시 묻지 않는다.
- 새로운 게임플레이 결정이 필요한 경우에만 질문한다.
- 범위를 임의로 확대하지 않는다.

이 명세는 구현 승인이며, 작업환경에서 가능한 파일 확인·코드 작성·빌드·수정·검증을 진행한다. 접근할 수 없는 게임 환경이나 필요한 자료가 있으면 정확한 장애 요인을 보고한다.

1. 제작할 모드 구성

서로 분리된 모드 두 개를 만든다.

A. 철기병 모드

중상급 근접 돌격 메카를 추가한다.

- 플레이어가 배양하고 통제하는 Biotech 메카.
- 일반 사이더의 전투 행동을 바탕으로 한다.
- 적에게 접근하며 충전하고, 첫 공격을 강화한다.

B. 메카 관리 모드

다음 기능을 제공한다.

1) 지정 자리에서 절전.
2) 위협 발생 시 비전투 인원 대피 및 전투 메카 집결.
3) 지정 메카들의 정기적인 포식동물 집단 소탕.

각 기능을 따로 켜고 끌 수 있게 한다.

독립성

- 철기병 모드는 관리 모드 없이 작동해야 한다.
- 관리 모드는 철기병 모드 없이 바닐라 메카를 대상으로 작동해야 한다.
- 함께 사용할 때 철기병도 관리 대상 메카로 정상 인식한다.
- 필수 DLC는 실제 사용하는 기능에 따라 최소한으로 선언한다. 사용자가 모든 DLC를 보유한다는 이유로 전부 의존성에 넣지 않는다.
- Def 이름과 Harmony 식별자 등에 고유 접두사를 사용한다.

2. 기존 환경 확인

사용자가 현재 사용하는 관련 모드:

- 메카나이터 통제 거리 무제한 모드.
- 충전량이 80% 이상이며 할 일이 없는 메카가 충전기에서 나온 뒤 자동으로 절전하는 모드.

정확한 모드명과 구현 방식은 집의 작업환경에서 확인한다.

확인할 사항:

- 실제 게임 버전과 빌드 번호.
- 활성 모드 목록과 로드 순서.
- 두 기존 모드의 메타데이터, 공개 소스 또는 설치된 코드의 동작.
- 기존 자동절전 모드가 절전 행동을 언제, 어떻게 지정하는지.
- 자동절전과 충전 복귀를 반복시키는 충돌 가능성.
- 게임 DLL 및 빌드에 필요한 참조 파일 위치.

기존 모드를 직접 수정하지 않는다. 필요한 호환 처리는 새 모드 내부에 둔다.

기존 자동절전 모드를 찾지 못하면 임의의 모드로 가정하지 말고, 독립적으로 진행할 수 있는 작업부터 수행한다.

3. 공통 행동 우선순위

기본 우선순위:

1) 플레이어의 직접 명령
2) 비상 대피·집결 및 이에 따른 전투
3) 포식동물 소탕
4) 평상시 작업·충전·자동절전

세부 원칙:

- 자동 기능이 플레이어의 명령을 매 틱 덮어쓰면 안 된다.
- 직접 명령을 받은 개체는 해당 명령이 진행되는 동안 자동 행동 배정에서 제외한다.
- 직접 명령이 끝난 뒤 자동 관리에 복귀할 수 있어야 한다.
- 다운·기절·사망·소유권 변경 등으로 행동 불가능해지면 관련 자동 작업을 안전하게 중단한다.
- 바닐라의 필수적인 작업 유효성 검사와 행동 불가능 조건을 우회하지 않는다.
- 같은 개체에 절전·소탕·집결 명령을 반복해서 교체하는 현상을 방지한다.
- 행동 취소 시 그 행동이 만든 임시 상태·예약·속도 보너스를 정리한다.

======================================================================
A. 철기병 모드
======================================================================

A1. 외형과 정체성

확정 이름: 철기병

외형은 사용자가 제공한 이미지가 기준이다.

- 켄타우로스형 하체.
- 밝은 장갑과 어두운 관절.
- 긴 머리 장식.
- 전방으로 길게 뻗은 창.
- 원거리 무장은 없는 근접 메카.

림월드 화면에서 식별하기 쉬운 방향별 텍스처를 준비한다.

- 첫 버전은 고정 방향별 스프라이트로 충분하다.
- 별도 다리 애니메이션은 필수 범위가 아니다.
- 이미지를 게임에 맞는 크기와 시점으로 재구성한다.
- 원본 이미지가 새 작업에 없다면 첨부를 요청한다.
- 임시 외형으로 기능을 검증했다면 최종 외형 완료와 구분해서 보고한다.

A2. 성능과 획득

확정 목표:

- 사이더보다 확실히 높은 성능의 중상급 메카.
- 사용자가 말한 “3~4티어”는 성능·생산 단계의 목표이며, 특정 공식 티어 체계를 의미하지 않는다.
- 정상적인 메카 배양으로 획득.
- 첫 버전은 플레이어 배양용으로 제작하고, 적 습격 편성 추가는 범위에서 제외한다.
- 강한 첫 타격이 특징이며, 원거리 화력이나 범위 공격은 추가하지 않는다.

아직 확정되지 않은 값:

- 체력과 부위 구성.
- 방어도.
- 평타 피해·공격 주기·관통력.
- 기본 이동속도.
- 대역폭.
- 생산 연구·배양기·재료·배양 시간.
- 에너지 소비.

위 값은 실제 1.7 사이더와 다른 바닐라 메카 데이터를 확인한 뒤, 중상급 돌격병이라는 목표에 맞춰 초기안을 정하고 조정 근거를 남긴다. 대화에서 예시로 나온 값을 확정 수치로 취급하지 않는다.

A3. 기본 전투 행동

- 일반 사이더의 근접 전투 행동을 기반으로 한다.
- 별도의 상시 적 탐색 AI를 새로 만들지 않는다.
- 기존 전투 행동이 선택한 대상을 활용한다.
- 돌격이 불가능하거나 쿨다운 중이면 일반 근접 공격을 수행한다.
- 관리 모드의 집결 기능 때문에 공격·추격 행동이 계속 취소되면 안 된다.

A4. 돌격 조작

- 수동 대상 지정 돌격 명령 제공.
- 자동 돌격 사용 토글 제공.
- 자동 돌격은 기본 활성화.
- 수동 명령이 자동 판단보다 우선.
- 토글 상태는 저장·불러오기 후 유지.

자동 돌격은 실제 근접 전투 행동 중 조건을 충족했을 때 사용한다. 돌격을 위해 일하지 않던 메카가 임의로 적을 찾아 맵을 돌아다니면 안 된다.

A5. 돌격 초기 설정

다음은 합의된 추천안을 바탕으로 한 초기 설정이며, 설정값과 동작 코드를 분리해 조정하기 쉽게 한다.

- 돌격 이동속도: 기본 이동속도의 1.5배
- 강화에 필요한 최소 유효 접근 거리: 3칸
- 최대 강화에 필요한 유효 접근 거리: 8칸
- 최대 첫 공격 피해: 기본 피해의 2.5배
- 재사용 대기: 720게임틱, 즉 12게임초

3~8칸 사이의 정확한 피해 곡선은 아직 확정되지 않았다. 초기 구현은 이해하기 쉬운 단조 증가 방식으로 정하고 실제 수치를 명시한다.

A6. 돌격 처리

1) 대상과 경로가 유효한지 확인한다.
2) 돌격 행동을 시작한다.
3) 바닐라 경로 탐색과 지상 이동을 사용한다.
4) 실제 이동에 따라 유효 접근 거리를 누적한다.
5) 근접 거리에서 창 공격을 한 번 시도한다.
6) 명중·빗나감과 관계없이 첫 공격 시도에 돌격을 소모한다.
7) 이후 일반 근접전으로 전환한다.

피해 처리:

- 강화는 해당 공격 한 번에만 적용한다.
- 단일 대상 피해만 준다.
- 별도 밀치기·범위 피해·추가 경직·벽 파괴를 넣지 않는다.
- 강화 피해가 여러 경로에서 중복 적용되지 않게 한다.
- 관통력까지 피해 배율로 자동 증폭시키지 않는다.
- 평상시 전체 피해 스탯을 지속적으로 올리는 방식은 피한다.

A7. 거리와 중단 조건

- 정지 시간으로 충전되지 않는다.
- 순간이동·강제 위치 변경은 접근 거리로 계산하지 않는다.
- 후퇴·왕복·빙빙 돌기로 충전량을 쌓을 수 없어야 한다.
- 작은 경로 보정은 허용하되 큰 우회로 충전량을 부당하게 얻지 않게 한다.
- 대상이 움직이는 경우도 고려한다.
- 막혀 있으면 충전되지 않는다.
- 최소 거리를 충족하지 못하면 강화 피해를 주지 않는다.

다음 상황에서 돌격 상태를 정리한다.

- 직접 명령으로 취소.
- 공격 대상 변경.
- 대상 사망·소멸·맵 이탈.
- 경로 실패.
- 다운·기절·사망.
- 돌격 행동 종료.
- 소유권이나 통제 조건 변경.

속도 보너스와 충전량이 남지 않아야 한다.

쿨다운은 돌격 시작 시 설정하고, 취소로 초기화되지 않도록 하는 것을 구현 기본안으로 한다. 인접 상태에서 반복 취소하며 강화 공격을 얻는 악용을 막는다.

======================================================================
B. 메카 관리 모드
======================================================================

B1. 사용자 설정과 관리 대상

맵마다 설정을 관리한다.

필요한 항목:

- 공통 안전구역.
- 전투 메카 집결 구역.
- 비상 상태 버튼.
- 개체별 대피 대상 체크.
- 메카별 전투 집결 대상 체크.
- 메카별 소탕 참여 체크.
- 메카별 절전 자리 배정.
- 기능별 활성화 여부.

확정된 대상 범위:

- 플레이어가 정상적으로 명령할 수 있는 개체.
- 대피 대상으로 체크한 사람.
- 활동구역 지정이 가능한 동물.
- 대피 대상으로 지정한 비전투 메카.
- 집결 대상으로 지정한 전투 메카.

제외:

- 우리 방식으로 관리하는 가축의 자동 대피.
- 죄수·방문객을 강제로 통제하는 기능.
- 다운된 사람이나 동물을 운반해서 구조하는 기능.
- 원정대나 다른 맵에 있는 개체를 불러오는 기능.

대피 대상은 사용자가 직접 고른다. 무기나 능력치를 보고 사람을 자동으로 전투원·비전투원으로 확정하지 않는다.

같은 메카를 비상 대피와 전투 집결에 동시에 지정하지 못하게 하거나, UI에서 명확하게 하나를 선택하도록 한다.

B2. 지정 자리에서 절전

배정

- 동물 잠자리처럼 설치할 수 있는 메카 전용 절전 자리를 제공한다.
- 개체별로 배정한다.
- 실제 동물 잠자리를 메카가 동물처럼 사용하도록 억지로 확장할 필요는 없다.
- 자리 배정 관계를 저장한다.

기존 자동절전 모드와의 관계

기존 모드가 절전할 시점을 판단한다.

새 기능은:

기존 자동절전 결정 → 배정 자리로 이동 → 기존 절전 동작

이 흐름을 연결하는 역할이다.

- 충전량 80% 조건을 별도 로직으로 중복 관리하지 않는다.
- 기존 모드가 이동을 취소하고 현재 위치에서 절전시키는 충돌을 방지한다.
- 기존 충전 복귀 로직을 방해하지 않는다.

위험한 자리

사용자는 다음처럼 배정할 예정이다.

- 비전투 메카: 집 안.
- 전투 메카: 킬존.

따라서 위험도가 높다는 이유만으로 배정 자리 복귀를 거부하면 안 된다.

단, 다음은 구분한다.

- 갈 수 있는 위험한 자리: 복귀 허용.
- 파괴되었거나 실제 경로가 없는 자리: 실패 처리 후 기존 절전 동작으로 복귀.
- 직접 명령이나 비상 행동 수행 중: 절전보다 해당 행동 우선.

위험 판정을 무시하기 위해 모든 폰의 경로 탐색 규칙을 전역 변경하지 않는다.

비상 상태

- 비상 집결 대상으로 지정된 전투 메카는 절전 중이어도 깨어나 집결한다.
- 대피 대상으로 지정된 메카는 안전구역으로 이동한다.
- 비상 행동 중 절전 자리 복귀가 이를 방해하지 않는다.
- 비상 해제 후 기존 자동절전 규칙으로 돌아간다.

B3. 비상 대피와 전투 메카 집결

구역 구성

맵마다 다음 두 구역을 지정한다.

1) 공통 안전구역
   - 사람·동물·비전투 메카가 공유.
   - 예: 주거구역 전체.

2) 전투 메카 집결 구역
   - 사용자가 지정한 전투 메카의 초기 집결 위치.
   - 예: 킬존의 엄폐물 뒤.

안전구역은 바닐라 활동구역 제한을 기본으로 사용한다.

- 대피 후 구역 안에서 가능한 생활과 작업은 계속할 수 있다.
- 구역 밖 경유까지 막는 별도 엄격한 경로 탐색은 구현하지 않는다.
- 직접 명령이 활동구역보다 우선하는 바닐라 동작을 존중한다.
- 메카에 같은 제한을 적용할 수 있는 정확한 방식은 1.7 구현을 확인한다.

비상 버튼

버튼 하나를 눌러 비상 활성화, 다시 눌러 해제한다.

자동 감지와 수동 조작의 상태를 구분한다.

- 위협 자동 감지 → 자동 비상 활성화.
- 해당 맵의 미해결 위협이 모두 해결됨 → 자동 비상 해제.
- 평상시에 버튼으로 활성화 → 수동 비상 상태 유지.
- 수동 비상 상태에서 버튼을 다시 누름 → 해제.
- 위협이 남았지만 버튼으로 해제 → 사용자 해제를 존중.
- 수동 해제 후 같은 위협이 계속 존재 → 즉시 다시 켜지지 않음.
- 수동 해제 후 새로운 위협 발생 → 자동으로 다시 활성화 가능.

수동 활성화를 위협이 없다는 이유로 즉시 자동 해제하면 안 된다.

수동 해제한 위협의 식별과 억제 상태는 저장·불러오기 후에도 일관돼야 한다. 기존 위협이 실제로 새로운 위험 단계로 전환되는 경우의 재발동 기준도 명시한다.

감지할 위협

사용자는 공격이 시작된 뒤에만 대피하는 것을 원하지 않는다.

다음을 포함한다.

- 적대 세력의 습격.
- 광란 동물의 위협.
- 공격 위험이 있는 곤충 출현.
- 적대 메카 군집.
- 아직 비활성 상태인 적대 메카 군집.
- 맵 내부에서 발생한 적대화.
- 정착민 등을 공격하거나 사냥하기 시작한 야생 포식동물.
- 설치된 DLC에서 이에 준하는 공격 위협.

일반 야생 포식동물은 존재 자체만으로 비상을 발동하지 않는다. 정기 소탕 대상으로 별도 관리한다.

단순히 특정 습격 이벤트 하나만 감지해서 “모든 위협 지원”이라고 보고하지 않는다. 실제 1.7과 설치된 DLC를 확인해 지원하는 위협 유형과 누락 가능성을 정리한다.

위협 해결

- 적이 잠시 시야에서 사라졌다는 이유로 해제하지 않는다.
- 여러 위협이 겹치면 하나를 해결해도 나머지가 남아 있는 동안 유지한다.
- 비활성 군집도 남아 있으면 위협으로 취급한다.
- 위협 유형에 따라 사망·격파·맵 이탈·적대 상태 해소 등을 확인한다.
- 빈 군집 구조물이나 일시적인 상태 때문에 영구 비상이 되는 일을 검증한다.

대피 처리

비상 시작 시:

1) 대상별 기존 활동구역 상태 저장.
2) 공통 안전구역 적용.
3) 진행 중인 일반 작업을 중단하고 대피.
4) 도착 후 안전구역 안에서 활동.

주의사항:

- 구역을 바꾸는 것만으로 즉시 대피했다고 간주하지 않는다.
- 스스로 움직일 수 없는 대상에게 이동 명령을 반복하지 않는다.
- 비상 중 대상이 이동 가능해졌을 때의 처리를 고려한다.
- 대피 지점에 도달할 수 없으면 실패를 알리고 경로 요청을 과도하게 반복하지 않는다.
- 대피 구역 미지정 시 정상 동작한 것처럼 표시하지 않는다.

비상 종료 시:

- 모드가 변경했던 활동구역 설정을 복원한다.
- 완료된 예전 작업을 무조건 재실행하지 않고 정상 AI로 복귀시킨다.
- 비상 중 사용자가 설정을 바꾼 경우 무조건 오래된 값으로 덮어쓰지 않도록 복원 규칙을 정한다.
- 모드가 변경하지 않은 징집·구역·작업 상태는 건드리지 않는다.

전투 메카 집결

- 비상 시작 시 지정 구역으로 집결시킨다.
- 한 칸에 모두 이동시키지 않고 유효한 위치에 분산한다.
- 집결 구역은 전투 행동을 가두는 경계가 아니다.
- 적과 교전하면 일반 바닐라 메카처럼 싸운다.
- 철기병은 일반 사이더 기반 행동으로 접근·공격하고, 조건에 맞으면 돌격한다.
- 적이 집결 구역 안으로 들어와야만 공격하도록 제한하지 않는다.
- 집결 명령을 반복해서 공격·추격을 취소하면 안 된다.
- 기존 전투 AI가 움직이지 않는 상태로 고정되는 구현도 피한다.

B4. 정기 포식동물 소탕

검사 주기

54,000게임틱마다 현재 맵의 소탕 대상 존재 여부를 한 번 검사한다.

- 현실 시간 타이머가 아니다.
- 일시정지 시 진행하지 않는다.
- 실제 900 TPS 유지 시 현실 약 1분이다.
- 게임 속도와 실제 TPS에 따라 현실 시간 간격은 달라진다.
- 저장·불러오기 후 검사 시점이 무한히 밀리거나 즉시 중복 검사되지 않게 한다.

대상

- 현재 맵에 존재.
- 살아 있는 야생 포식동물.
- 정착지나 다른 세력 소유 동물 제외.
- 1.7의 실제 데이터에 따른 포식동물 판정을 사용.
- 특정 동물 이름을 하드코딩한 목록에만 의존하지 않는다.
- 맵을 떠났거나 길들여져 소유권이 바뀐 동물은 대상에서 제외.

참여 메카

사용자가 소탕 참여로 체크한 메카 중:

- 현재 맵에 존재.
- 정상적으로 통제 가능.
- 이동·공격 가능.
- 충전량 20% 이상.
- 직접 명령 수행 중이 아님.
- 비상 대피·집결 중이 아님.

집단 행동

사용자는 선정된 메카들이 함께 한 마리씩 공격해 포식동물을 모두 소탕하기를 원한다.

- 각 메카가 서로 다른 동물을 독립적으로 찾아 흩어지면 안 된다.
- 공유하는 현재 소탕 대상을 둔다.
- 같은 대상에 여러 메카가 공격하는 것은 정상 동작이다.
- 중복 방지의 대상은 별도 소탕 작업의 중복 생성이며, 집단 공격 자체를 막으면 안 된다.
- 한 마리를 처리한 뒤 다음 대상으로 이동한다.
- 접근 가능한 대상이 없으면 종료한다.
- 다운된 포식동물은 사망할 때까지 마무리한다.
- 이동이 느린 메카 하나 때문에 전체가 무한 대기하지 않게 한다.

완전한 대형 이동이나 복잡한 전술 AI는 범위에 넣지 않는다. 함께 출동하고 공유 대상을 공격하는 데 필요한 최소 동기화만 구현한다.

에너지 조건

- 20% 이상일 때 출동 가능.
- 출동 후 20% 아래가 되었다고 바로 이탈하지 않는다.
- 10% 이하가 되면 해당 메카는 소탕에서 빠지고 충전하러 복귀한다.
- 나머지 메카는 계속 진행.
- 참여자가 모두 이탈하면 소탕 종료.
- 충전기가 없는 경우 실패 상태를 처리하고 무한 작업 반복을 막는다.

시체 처리

소탕으로 죽인 동물의 시체는 금지를 해제한다.

- 운반·도축이 가능하도록 허용한다.
- 실제 운반은 기존 작업 담당자가 수행.
- 실제 도축은 기존 도축 작업 설정에 따름.
- 모드가 새 도축 작업을 자동으로 생성하거나 전 맵의 다른 시체까지 금지 해제하지 않는다.
- 다른 원인으로 죽은 현재 소탕 대상도 소유권 등 조건을 다시 확인한 뒤 처리한다.

종료와 중단

다음 상황에서 대응한다.

- 대상 사망: 다음 대상 선택.
- 대상 소멸·맵 이탈·소유권 변경: 현재 대상 취소.
- 대상 접근 불가: 이번 소탕에서 건너뛰기.
- 플레이어 직접 명령: 해당 메카를 자동 소탕에서 제외.
- 비상 발생: 소탕 중단 후 대피·집결 우선.
- 참여자 다운·사망: 참여 목록에서 제거.
- 다음 54,000틱 검사 시점에 기존 소탕 진행 중: 새 소탕을 중복 생성하지 않음.

실패한 대상의 경로를 매 틱 다시 계산하지 않는다.

소탕 종료 후에는 정상 작업·충전·기존 자동절전 흐름으로 복귀한다.

비상 감지와의 충돌 방지

소탕 대상의 정상적인 반격을 무조건 새로운 비상으로 판정하면:

소탕 시작 → 포식동물 반격 → 비상 → 소탕 취소

가 반복될 수 있다.

따라서:

- 소탕 대상이 출동한 소탕 메카와 싸우는 상황은 그 자체로 비상을 발동하지 않는다.
- 같은 동물이 정착민 등 다른 보호 대상을 공격하는 상황까지 일괄 무시하지 않는다.
- 소탕과 관계없는 새로운 공격 위협은 정상적으로 비상을 발동한다.

C. 성능 설계
======================================================================

C1. 목표와 보고 기준

- 철기병 약 5기를 운용하는 상황을 고려한다.
- 사용자의 평소 실제 처리 속도는 약 900 TPS다.
- 이것은 요구되는 고정 성능 보장이 아니라 비교 기준이다.
- 추가 개체 자체의 비용과 커스텀 기능의 비용을 구분한다.
- “틱 저하 없음”, “정확히 몇 TPS만 감소” 같은 실측 없는 주장을 하지 않는다.

C2. 피해야 할 구현

- 매 틱 모든 폰·동물·건물을 순회.
- 메카마다 별도로 전체 맵의 소탕 대상을 검색.
- 매 틱 돌격 경로를 새로 계산.
- 대피·집결 명령을 매 틱 재지정.
- 실패한 경로를 짧은 간격으로 무한 재시도.
- 매 틱 임시 목록 생성과 불필요한 할당.
- 대상과 무관한 모든 폰의 전투 동작에 무거운 Harmony 처리.
- 계속 쌓이기만 하는 위협·시체·작업 참조.

C3. 권장 구조

- 맵 단위로 비상 상태·소탕 상태·설정을 관리.
- 개체 단위로 필요한 최소 상태만 저장.
- 위협 감지는 가능한 실제 상태 변화 지점에서 처리.
- 이벤트 감지만으로 누락되는 부분은 필요 범위의 저빈도 재확인으로 보완.
- 위협 종료 확인과 새 위협 검색을 구분.
- 시간 간격 처리는 게임틱 기준의 다음 실행 시각을 저장.
- 한꺼번에 많은 개체가 처리되는 작업은 필요하면 분산.
- 경로 탐색은 바닐라 기능을 활용.
- 상세 디버그 로그는 기본 비활성화.

54,000틱 소탕 검사는 소탕 후보를 찾는 주기다. 진행 중인 공격의 유효성 검사까지 54,000틱마다만 수행하라는 뜻은 아니다.

D. 저장·불러오기 및 실패 처리
======================================================================

다음을 저장하거나 안전하게 재구성한다.

- 개체별 체크 상태.
- 절전 자리 배정.
- 공통 안전구역과 집결 구역.
- 기능 활성화 설정.
- 비상 모드의 자동·수동 구분.
- 수동 해제한 위협의 재발동 억제 상태.
- 기존 활동구역 복원에 필요한 정보.
- 다음 소탕 검사 게임틱.
- 진행 중인 소탕의 대상·참여자.
- 철기병 자동 돌격 토글.
- 돌격 쿨다운.
- 진행 중인 돌격의 일관성에 필요한 상태.

불러온 직후 참조 대상을 재검증한다.

- 삭제된 구역.
- 파괴된 절전 자리.
- 죽거나 맵을 떠난 폰.
- 소멸한 공격 대상.
- 변경된 소유권.
- 사라진 위협.
- 존재하지 않는 작업.

저장 데이터에 참조가 있다는 이유만으로 대상이 여전히 유효하다고 가정하지 않는다.

기능을 끄면 해당 기능이 만든 임시 상태를 정리한다. 특히 비상 대피를 끌 때 적용한 구역 제한이 영구히 남지 않아야 한다.

기존 세이브에 추가할 수 있는지 검증한다. 모드 제거가 안전하다고 검증 없이 보장하지 않는다.

한국어 이름·설명·버튼을 제공한다.

필수 표시:

- 메카별 절전 자리 배정.
- 철기병 자동 돌격 토글과 돌격 재사용 대기.
- 미설정 구역·도달 불가 등 사용자가 조치해야 할 실패.

UI에서 사용하지 않는 내부 구현 용어를 노출하지 않는다.

매 틱 반복되는 알림이나 로그를 만들지 않는다. 같은 실패는 묶거나 재알림을 제한한다.

======================================================================
F. 구현 순서
======================================================================

문제를 분리해서 확인할 수 있도록 단계적으로 진행한다.

1) 실제 게임·기존 모드·빌드 환경 확인.
2) 두 모드의 독립적인 최소 로딩 구조 작성.
3) 철기병의 기본 배양·통제·일반 근접전 구현.
4) 수동 돌격 구현 및 상태 정리 검증.
5) 자동 돌격 연결.
6) 절전 자리와 기존 자동절전 모드 연결.
7) 수동 비상 버튼·대피·집결·복원 구현.
8) 자동 위협 감지와 자동 해제 연결.
9) 집단 소탕과 에너지·시체 처리 구현.
10) 저장·불러오기와 기능 간 전환 검증.
11) 외형·한국어 UI 마무리.
12) 성능 비교와 배포 폴더 정리.

작업 중 발견한 실제 1.7 API와 기존 모드 동작은 짧은 구현 메모로 남긴다. 추후 다른 모델이 작업을 이어받아도 같은 확인을 반복하지 않게 한다.

======================================================================
G. 필수 검증 사례
======================================================================

G1. 철기병

- 배양·출생·통제·충전 정상 작동.
- 일반 근접전이 정상 작동.
- 3칸 미만에서 강화되지 않음.
- 최대 강화 상한 적용.
- 첫 공격 명중 후 평타에 강화가 남지 않음.
- 첫 공격 빗나감 후에도 강화가 소모됨.
- 정지·왕복·순간 위치 변경으로 부당하게 충전되지 않음.
- 문·벽·좁은 통로·움직이는 대상 처리.
- 돌격 취소 후 이동속도 복원.
- 대상 사망·다운·기절·경로 실패 처리.
- 저장·불러오기 후 쿨다운 정상 유지.

G2. 절전

- 기존 80% 자동절전 조건과 충돌하지 않음.
- 지정 자리로 이동한 뒤 절전.
- 위험한 자리라는 이유만으로 복귀 거부하지 않음.
- 배정되지 않은 메카의 기존 동작 유지.
- 자리 파괴·경로 차단 처리.
- 비상 시 절전보다 대피·집결 우선.
- 절전과 충전 사이의 무한 반복 없음.

G3. 비상

- 자동 발동과 자동 해제.
- 수동 발동이 위협 부재로 즉시 해제되지 않음.
- 수동 해제 직후 같은 위협으로 재발동하지 않음.
- 새로운 위협 발생 시 다시 발동.
- 비활성 메카 군집 감지.
- 복수 위협 중 하나만 해결했을 때 상태 유지.
- 체크한 대상만 대피.
- 기존 활동구역 복원.
- 구역 미지정·삭제·도달 불가 처리.
- 직접 명령이 자동 대피와 충돌하지 않음.
- 전투 메카가 집결 후 정상적으로 접근·공격.
- 집결 명령이 전투를 반복 취소하지 않음.

G4. 소탕

- 54,000게임틱 주기 준수.
- 포식동물이 없으면 불필요한 출동 없음.
- 야생 포식동물만 선정.
- 소유 동물 제외.
- 여러 메카가 공유 대상을 함께 공격.
- 한 마리 처리 후 다음 대상으로 진행.
- 다운된 대상 마무리.
- 시체 금지 해제.
- 20% 미만 메카 출동 제외.
- 진행 중 10% 이하 메카 이탈.
- 접근 불가 대상 무한 재시도 없음.
- 소탕 진행 중 검사 시점이 와도 중복 생성 없음.
- 소탕 대상 반격으로 비상이 무한 반복되지 않음.
- 새로운 실제 위협 발생 시 소탕 중단.

G5. 조합과 저장

- 철기병 모드만 활성화.
- 관리 모드만 활성화.
- 두 모드 함께 활성화.
- 기존 자동절전·거리 무제한 모드와 함께 활성화.
- 돌격 도중 비상 상태 변경.
- 절전 중 소탕 출동.
- 소탕 중 비상 집결.
- 각 기능 실행 중 저장·불러오기.
- 기능을 끈 뒤 잔여 상태 정리.
- 개체 사망·소유권 변경·맵 이탈.

- 정착민·동물·전체 메카 수.
